# Shopify's agent ecosystem, mapped to the tasks of the product lifecycle

Date: 2026-10-24. Same frame as the [Stripe map](../competitive-teardown-stripe-knowledge-agents/02-pdlc-agent-ecosystem-map.md). Visual version: [01-pdlc-agent-ecosystem-map.html](01-pdlc-agent-ecosystem-map.html), generated by [01-pdlc-agent-ecosystem-map.build.py](01-pdlc-agent-ecosystem-map.build.py).

Built only from filed source notes in `../../research/sources/`. Each handoff is marked **documented** (a Shopify source says it happens), **inferred** (consistent with the sources but not stated) or **unknown**.

Almost all evidence is first-party: Shopify's engineering blog, Tobi Lütke, and Farhan Thawar. No independent source observes any of these handoffs. Dates matter: the River evidence runs Mar–Oct 2026, while the goal-setting and GSD evidence is from 2023 and 2025.

## Why the frame fits Shopify, and where it differs

- **Tasks, not titles, fits Shopify well.**
  - River is used by "7,000+ people" across 5,170 channels, which is nearly the whole company ([Under the River](../../research/sources/shopify-engineering-under-the-river.md)).
  - With Remote Dev, "a web developer can fix a bug, a designer can iterate on a UI, and a PM can test a feature, all through Slack" ([Remote Dev](../../research/sources/shopify-engineering-remote-dev.md)).
- **The overlay is GSD, Shopify's project process, not a whiteboard chain.** Every project passes five reviewed phases: Proposal, Prototype, Build, Release, Results ([Lenny, Glen Coates](../../research/sources/lenny-how-shopify-builds-product.md), 2023). Since April 2025 the Prototype phase "should be dominated by AI exploration" ([Tobi memo](../../research/sources/x-tobi-reflexive-ai-usage-memo.md)). The diagram shows GSD phases where Stripe's map shows its whiteboard chain.
- **No rows added or split.** The ten row names are kept. One structural difference is drawn instead of a new row: **learning is a loop that feeds every task**, not a final step. Nightly "dreaming", corpus mining and a thread classifier rewrite the skills and memory River uses everywhere. It is shown as a return arrow into the shared layer.
- **Research, intent, plan and code collapse into one agent and one place.** At Stripe a different agent covers each task (Kai, Harbor, Orbit, Minions). At Shopify one agent, River, does research, intent shaping, plan push-back and code inside the same public Slack thread. Specialised agents (security remediation, PR review, Helix, Dispatch) are profiles or pipelines around that core.

## The short answer: where does context break between research, intent and plan, across people?

**Inside Slack, mostly it doesn't: the public thread is the handoff.**
1. **The four tasks happen in one place.** People discuss, then ask "Hey River, can you summarize this, create a ticket, or maybe make a diagram... or maybe even create a prototype", and River "usually offers to go fix it" ([Knowledge Project](../../research/sources/fs-knowledge-project-tobi-lutke-ai-agents.md); [Tobi reply](../../research/sources/x-tobi-river-replies-may-2026.md)).
2. **People hand off by joining the same thread.** "A second human... drops in with a constraint or a redirect. River incorporates the new context without losing the conversation" ([Under the River](../../research/sources/shopify-engineering-under-the-river.md)). Same-thread co-writing links grew from 61,680 to 171,853 between Mar and Sep 2026 ([chart](../../research/sources/x-tobi-river-floods-shopify-chart.md)).
3. **Later people start from the thread.** "The next person to hit a similar problem starts from this thread, not from a blank prompt". Channel and per-person memory is injected at the start of each session. All of this is self-reported, and nobody has measured how often the next person actually finds the thread.

**It breaks at the edges of the thread:**
- **Before research.** No source connects customer conversations, the yearly themes, or a GSD Proposal to a River thread. River "can see our product management system" ([Thawar](../../research/sources/venturebeat-beyond-the-pilot-farhan-thawar.md)), but whether a GSD project and its threads are linked is not described.
- **From thread to durable artifact.** There is no structured intent or plan object: the thread, a ticket, a Quick site or a PR stands in for it. How a Quick prototype becomes production code is not described. "Intent documents" live in the World monorepo, but who writes them, and when, is unknown.
- **Private and sensitive work.** River refuses DMs and private channels ("you can't go into a private channel and say, 'Hey, River, help me build'"). Research done under HR, legal, security or customer-data constraints cannot enter the shared context, and how it reaches the agent's work is unknown.
- **Findability.** Discovery relies on Slack search, per-channel memory and mined skills. An X user's objection that past about five people "anyone's really gonna be scrolling other people's slack channels" was never answered directly ([Tobi replies](../../research/sources/x-tobi-river-replies-may-2026.md)).

**Against Stripe.** Stripe's break is between agents: Kai's single-user sessions don't reach Orbit. Shopify avoided that break by putting one agent in one shared place. The price is privacy (no private mode) and structure (no intent or plan artifact). The seam that remains is between the conversation and the formal process, GSD, and the durable artifact.

## What it means for our options

- **A single shared place can remove the research → intent → plan seam that Stripe left to people,** if the target org accepts working in public. This links the [trust-privacy-defaults](../../options/DIMENSIONS.md#trust-privacy-defaults-trust-and-privacy-defaults-for-sessions-and-context) and [agent-interface](../../options/DIMENSIONS.md#agent-interface-agent-interface-own-app-chat-or-embedded) choices to the lifecycle seam: the same decision that drives learning also drives handoff.
- **The thread is not an intent standard.** Shopify keeps its formal gates (GSD) separate from the agent conversation, with no documented link between them. For orgs that need reviewable specs (regulated settings), an explicit intent artifact is still needed ([intent-shaping-and-spec](../../options/DIMENSIONS.md#intent-shaping-and-spec-intent-shaping-mode-and-spec-standard)).
- **One general agent with profiles, rather than one agent per task.** This is the opposite unit to Stripe's per-task agents ([work-structure](../../options/DIMENSIONS.md#work-structure-how-structured-the-work-is-what-agent-shape-fits-and-the-unit-of-an-agent)). Structured, narrow jobs (security remediation, migration, scanning) still get their own pipelines.
- **Learning as a loop across all tasks** (dreaming, corpus mining, a classifier) depends on transcripts being available, which is a consequence of public-by-default ([context-and-memory](../../options/DIMENSIONS.md#context-and-memory-context-and-memory)).

Key questions:

2. How often does a later person actually reuse an earlier River thread, as opposed to the corpus being mined into skills? — *answered by:* Shopify's own `river_sessions` data; a pilot metric for us.
3. Where do customer conversations enter the agent's context at Shopify, if at all? — *answered by:* more research (talks by Shopify PMs or researchers).

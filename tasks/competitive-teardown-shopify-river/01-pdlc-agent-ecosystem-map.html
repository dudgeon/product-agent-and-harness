Where Shopify’s agents sit in the product lifecycle, task by task

Same frame as the Stripe map: rows are tasks, not job titles. At Shopify one agent, River, does research, intent, planning and code in a public Slack thread that nearly the whole company uses. Each handoff is marked documented, inferred or unknown. Every figure is Shopify’s own.

Inside the thread, context mostly doesn’t break. At its edges, it does

  1. The public thread is the handoff. People discuss, then ask River to “summarize this, create a ticket… make a diagram… create a prototype”, and River “usually offers to go fix it”. Research, intent, plan and code happen in one place.
  2. People hand off by joining. “A second human… drops in with a constraint or a redirect”; same-thread co-writing links grew from 61,680 (March) to 171,853 (September 2026). Later people start “from this thread, not from a blank prompt” (claimed, not measured).
  3. It breaks at the edges. No source links customer conversations, yearly themes or GSD proposals to River threads. There is no intent or plan artifact beyond the thread, ticket, Quick site or PR. How a Quick prototype becomes production code is not described. River refuses DMs and private channels, so sensitive research never enters the shared context.

Against Stripe: Stripe’s break is between agents (Kai’s single-user sessions don’t reach Orbit). Shopify avoided it with one agent in one shared place, at the price of privacy and of structure. The remaining seam is between the conversation and the formal process (GSD) and the durable artifact.

What it means for our options

  • One shared place can remove the research → intent → plan seam that Stripe left to people, if the org accepts working in public. The same default that drives learning drives handoff.
  • The thread is not an intent standard. Shopify keeps its formal gates (GSD) apart from the agent conversation, with no documented link between them. Orgs that need reviewable specs still need an explicit intent artifact.
  • One general agent with profiles, not one agent per task. This is the opposite unit to Stripe’s; narrow, structured jobs (security, migration, scanning) still get their own pipelines.
  • Learning is a loop across all tasks, and it depends on transcripts being available, which is a consequence of public-by-default.

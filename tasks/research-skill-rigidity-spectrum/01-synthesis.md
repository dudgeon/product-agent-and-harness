## A. Bottom line

1. **A skill is a score, not a dial.** Every vendor guide and every real skill file we read sets rigidity one step at a time, not once for the whole skill. Anthropic's authoring guide matches "degrees of freedom" (prose, parameterised pseudocode, exact script) to how fragile and variable each step is; its own skills do the same (docx is exact commands plus validators, frontend-design is a persona plus defaults to avoid, skill-creator keeps the conversation loose but pins JSON field names). OpenAI, Google, Microsoft and LangChain all say to choose code or model per step and put code where a rule must hold. ([skill authoring](../../research/sources/anthropic-skill-authoring-best-practices.md), [docx](../../research/sources/anthropics-skills-docx.md), [frontend-design](../../research/sources/anthropics-skills-frontend-design.md), [skill-creator](../../research/sources/anthropics-skills-skill-creator-skill-md.md), [OpenAI orchestration](../../research/sources/openai-agents-sdk-multi-agent-orchestration.md), [ADK](../../research/sources/google-adk-docs.md), [Agent Framework](../../research/sources/microsoft-agent-framework-overview.md), [LangChain](../../research/sources/langchain-what-is-an-agent.md): first-party.) So the useful unit is a set of dimensions scored per step, with the whole skill described by its profile.

2. **Rigid and loose nest in two directions, and both ship.** Model-judged nodes inside a code-fixed scaffold (Stripe blueprints: "putting LLMs into contained boxes"; LangGraph nodes; 12-factor "own your control flow"), or code islands inside a model-chosen flow (Copilot Studio topics as "mini-agents"; Anthropic's advice to consolidate a procedure into one tool). A single slider cannot tell these apart; the profile has to record which layer is in charge. ([Minions part 2](../../research/sources/stripe-minions-part-2.md) first-party; [Copilot Studio topics](../../research/sources/microsoft-copilot-studio-topics-as-mini-agents.md) first-party; [12-factor](../../research/sources/humanlayer-12-factor-agents-own-your-control-flow.md) anecdote; [writing tools](../../research/sources/anthropic-writing-tools-for-agents.md) first-party.)

3. **"Make it rigid" is three separate decisions: where a check fires, who judges it, and whether it can fail open.** Claude Code hooks and OpenAI guardrails fire at fixed points but the judge can be a script, a model call or a tool-using agent; hooks enforce only on exit code 2 and a timed-out hook lets the action through; OpenAI guardrails run in parallel by default, so the agent may already have acted. A rigid gate is only rigid if it is built fail-closed and runs before the side effect. ([hooks reference](../../research/sources/anthropic-claude-code-hooks-reference.md), [hooks guide](../../research/sources/anthropic-claude-code-hooks-guide.md), [Agent SDK permissions](../../research/sources/anthropic-agent-sdk-permissions.md), [guardrails](../../research/sources/openai-agents-sdk-guardrails.md): first-party.) Shopify's rule from running River at scale states the split: "Prompts are the right place to express judgment and the wrong place to express a guarantee." ([River remediation](../../research/sources/shopify-engineering-river-vulnerability-remediation.md) first-party.)

4. **Checklists work through the behaviour they force, not the form, and agents fail the same way people do.** The WHO surgical checklist was associated with deaths falling from 1.5% to 0.8% in eight hospitals (before/after, no control); when Ontario mandated checklists in 101 hospitals, outcomes did not move, and interviews found checklists "often inaccurately documented as complete". Claude Code's agent-teams docs admit task status can lag and the lead can declare done early; in a 1,642-trace study of multi-agent failures about 24% were verification failures. A process artifact needs its own check that the work happened, separate from the ticks. ([Haynes NEJM](../../research/sources/nejm-haynes-surgical-safety-checklist.md), [Urbach NEJM](../../research/sources/nejm-urbach-ontario-surgical-checklists.md), [Gagliardi](../../research/sources/plosone-gagliardi-checklist-adherence.md), [MAST](../../research/sources/arxiv-why-multi-agent-llm-systems-fail.md): independent; [agent teams](../../research/sources/anthropic-claude-code-agent-teams.md) first-party.)

5. **The best-performing form of a standard is checkable items read holistically, and exemplars are an input to it, not a rung of their own.** In 45 medical assessment studies checklists and holistic rubrics had the same inter-rater reliability (0.81 vs 0.78) but the rubric transferred across tasks; for model judges, decomposing into yes/no items raised agreement with humans from 46.4% to 52.2%, while fixed weighted sums proved brittle and the best rubric form was self-contained checkable statements tagged by importance and read as a whole. Reference answers steady judges (one study's grading failure rate fell from 70% to 15% with a reference). A rubric exposes expert disagreement but does not remove it: a 262-physician rubric still only matched physician-physician agreement. ([Ilgen](../../research/sources/medu-ilgen-checklists-vs-global-rating-scales.md), [TICK](../../research/sources/arxiv-tick-checklist-evaluation.md), [Rubrics as Rewards](../../research/sources/arxiv-rubrics-as-rewards.md), [Zheng](../../research/sources/arxiv-zheng-judging-llm-as-a-judge.md): independent; [HealthBench](../../research/sources/arxiv-openai-healthbench.md) first-party.)

6. **Stance toward the human is a causal lever with the strongest independent evidence in this whole research question.** The same GPT-4 with tutor prompts (hints, not answers) raised practice scores 127% and removed most of the learning harm that the unrestricted model caused (a 17% drop on the unassisted exam); explanation without a recommendation produced learning where recommendation plus explanation did not; framing findings as questions improved people's reasoning even when the AI was always right; a devil's-advocate agent arguing against the AI's own recommendation improved appropriate reliance at no perceived workload cost. ([Bastani PNAS](../../research/sources/pnas-bastani-generative-ai-can-harm-learning.md), [Gajos and Mamykina](../../research/sources/arxiv-gajos-mamykina-ai-assistance-incidental-learning.md), [Danry CHI](../../research/sources/acm-danry-dont-just-tell-me-ask-me-chi2023.md), [Chiang IUI](../../research/sources/acm-chiang-llm-powered-devils-advocate-iui2024.md): independent, randomised.) Skills built to make the human think are now a recognisable genre with a shared design (one question at a time with a guess attached, tied to something specific in the work, an explicit stop rule, "never ask what you can read", and listed cases where asking would be paternalistic). ([discernment-nudge](../../research/sources/anthropics-skills-discernment-nudge.md), [doc-coauthoring](../../research/sources/anthropics-skills-doc-coauthoring.md), [PM plugin skills](../../research/sources/anthropics-kwp-pm-plugin-skills.md): first-party; [Superpowers](../../research/sources/obra-superpowers-skills.md), [Osmani](../../research/sources/addyosmani-agent-skills.md): anecdote.)

7. **Over-reliance is the default and it worsens as the agent improves; "human in the loop" is not automatically better.** Recruiters with a 75%-accurate AI beat those with an 85%-accurate one because they kept checking; consultants with GPT-4 were 23 points worse on a task outside the model's competence; endoscopists' detection rate in non-AI procedures fell from 28.4% to 22.4% within three months of AI being introduced; across 100+ experiments human-AI combinations averaged worse than the better party alone, losing on decision tasks and gaining on creation tasks. Cognitive forcing functions reduce over-reliance but are the least liked designs. ([Dell'Acqua](../../research/sources/hbs-dellacqua-falling-asleep-at-the-wheel.md), [BCG](../../research/sources/bcg-how-people-create-and-destroy-value-with-gen-ai.md), [Budzyń Lancet](../../research/sources/lancet-budzyn-endoscopist-deskilling-after-ai.md), [Vaccaro](../../research/sources/arxiv-vaccaro-when-human-ai-combinations-are-useful.md), [Buçinca](../../research/sources/arxiv-bucinca-cognitive-forcing-functions.md): independent.) Autonomy settings also drift toward autonomy with experience and by vendor default (Claude Code auto-approve-all rose from about 20% to over 40% of sessions with experience; interactive sessions now start in auto mode). ([autonomy study](../../research/sources/anthropic-measuring-agent-autonomy.md), [permission modes](../../research/sources/anthropic-claude-code-permission-modes-docs.md): first-party.)

8. **Taste is encoded negatively, and exemplar-heavy skills homogenise.** Anthropic's own taste skill carries no rubric and no exemplars: a persona, a few hard rules, a list of named AI defaults to avoid, and a process that forces a deliberate choice. Three peer-reviewed studies find model help raises individual quality and narrows collective diversity (stories more creative but more alike; ideas 41% less diverse at BCG), and the diversity loss comes from the tuned model's contributions. A shared PM skill applied to every PRD risks a homogenised portfolio. ([frontend-design](../../research/sources/anthropics-skills-frontend-design.md) first-party; [Doshi and Hauser](../../research/sources/sciadv-doshi-hauser-generative-ai-creativity.md), [Anderson](../../research/sources/arxiv-anderson-homogenization-effects-llm-ideation.md), [Padmakumar and He](../../research/sources/arxiv-padmakumar-he-content-diversity.md): independent.)

9. **Stale process records become wrong instructions once agents read them.** Two 2026 practitioner accounts describe agents following obsolete decision records and bloating them when asked to update; the fix layers deterministic CI for structure and drift, a model check of code against records, and a human who attests ("AI checks; humans attest"). Nygard's 2011 rules (small, numbered, immutable, superseded rather than edited) already fit agents. ([Davidson](../../research/sources/duncandavidson-coding-agents-love-decision-records.md), [Codeminer42](../../research/sources/codeminer42-stale-docs-prompt-injection.md), [Nygard](../../research/sources/nygard-documenting-architecture-decisions.md): anecdote.)

10. **Skills improve mostly through curated corrections; eval-driven loops are the documented ideal, not the norm; self-rewriting has named failure modes.** Shipped products keep a human in the curate step (Devin proposes knowledge from corrections, Claude Code `/insights` proposes instruction lines, Warp's improver opens a PR); research loops improve in proportion to the honesty of their feedback signal, and whole-file self-rewrites suffer "brevity bias" and "context collapse". No PM skill we found ships with evals. ([Devin knowledge](../../research/sources/devin-docs-knowledge.md) vendor claim; [insights](../../research/sources/vincentqiao-claude-code-insights.md), [Claude Code creator](../../research/sources/infoq-claude-code-creator-workflow.md) anecdote; [ACE](../../research/sources/arxiv-agentic-context-engineering.md), [Dynamic Cheatsheet](../../research/sources/arxiv-dynamic-cheatsheet.md), [GEPA](../../research/sources/arxiv-gepa-reflective-prompt-evolution.md): independent.)

11. **Nothing here is measured for product work.** No source compares code, model and human gates on error rates; no source compares rule-heavy with reason-heavy wording; no PM-domain study of model-rubric agreement with experienced PMs exists; "context graph" is an investment thesis with no data. The strongest evidence is from education, medicine, code review and human-factors research. (Judgment across all tracks.)

## B. Why one spectrum is the wrong picture

Geoff's prompt pictured a single line from rigid, step-by-step, if-then workflows to loose, taste-driven ones. The evidence says three things against a single line.

- **The unit is the step.** Track 6 of the runtime taxonomy already found that the structured/unstructured distinction belongs to a job step, not a person or a tool ([Track 6](../research-agent-runtime-patterns-taxonomy/track-6-work-structure-fit.md)). This research confirms it from the other side: every skill file sets its freedom per step, and the human-factors literature splits automation per task stage (acquire information, analyse, decide, act), with a different level at each ([Parasuraman, Sheridan and Wickens](../../research/sources/ieee-parasuraman-sheridan-wickens-types-and-levels-of-automation.md) independent). A PM skill can be fully automated at acquisition and analysis and human-chosen at decision.
- **Rigidity has several independent sources.** Who picks the step, what checks it, what the bar is, who decides, how the skill treats the person, what it leaves behind, how it learns. Two skills can be equally "rigid" on one and opposite on another: docx is rigid in path but explains every rule; a Cursor rules file is loose in path but bare of reasons ([Track E critique](scratch/track-e-practitioner-skills-judgment.md)). Shneiderman's point stands for agents: human control and automation are two axes, and the goal is high on both ([Shneiderman](../../research/sources/ijhci-shneiderman-human-centered-ai-reliable-safe-trustworthy.md) independent).
- **Two layers of one artifact.** The common pattern is a deterministic check on the process artifact (a record exists, frontmatter is valid, conversations are resolved, a task is marked done) and judgment on the content ([protected branches](../../research/sources/github-docs-protected-branches.md) first-party; [Codeminer42](../../research/sources/codeminer42-stale-docs-prompt-injection.md) anecdote; [agent teams](../../research/sources/anthropic-claude-code-agent-teams.md) first-party). Spec-driven toolchains do the same: folders, task states and hooks are fixed; the text inside is model-written and human-reviewed ([Kiro hooks](../../research/sources/kiro-hooks-docs.md), [Kiro steering](../../research/sources/kiro-steering-docs.md), [OpenSpec](../../research/sources/github-openspec-readme.md): first-party). So "rigid vs loose" often describes two layers of the same artifact, not the whole skill.

The picture that fits: **seven dimensions, each scored per step, with the whole skill described by its profile.** The sections that follow give each dimension's poles, the techniques at each point with real examples, and the evidence quality. Section D adds two modifiers that change the right profile without being dimensions of the skill itself.

## C. The seven dimensions

### C.1 Path: who picks the next step

**Poles.** Code-fixed sequence; model-chosen within a code scaffold; code islands inside a model-chosen flow; fully model-chosen (a loop with a stopping condition); human-chosen (the person drives, the agent fills in). LangChain's refinement: the model may control a step's output, the next step, or which steps exist at all ([LangChain](../../research/sources/langchain-what-is-an-agent.md) first-party). Runtime determinism (durable, replayable execution) is a separate engineering property: Temporal's orchestration is deterministic while the plan and every tool call are model-chosen ([Temporal](../../research/sources/temporal-dynamic-ai-agents.md) vendor claim).

**What the evidence says about choosing.** Vendors agree: code where a rule must always hold, model where the path cannot be written down, and grade the outcome, not the path ("it's often better to grade what the agent produced, not the path it took", [evals post](../../research/sources/anthropic-demystifying-evals-ai-agents.md) first-party). The independent production study found deployed agents are short and constrained (68% run at most 10 steps before a human intervenes), so constraint is what reliability work produces ([production study](../../research/sources/arxiv-measuring-agents-in-production.md) independent). Structure that compensates for model weakness decays (Ramp's Policy Agent moved from a fixed chain to an agentic loop, [Ramp lessons](../../research/sources/pragmatic-engineer-ramp-lessons-new-ai-product.md) first-party); structure the work demands (verification, audit, permissions, repeatability) persists. **No source measures classic against model-chosen orchestration on outcomes.**

### C.2 Check: where a gate fires, who judges, and whether it can fail open

This is the dimension Geoff's "if-then logic" picture most often collapses into. The evidence splits it into three sub-choices.

- **Enforcement point.** Advisory instruction in the prompt ("a skill is a control, though an advisory one", [SDLC playbook](../../research/sources/claude-ai-native-sdlc-playbook.md) first-party) → a harness-enforced checkpoint (hook, guardrail tripwire, graph node, required CI check) → a platform rule that binds in every mode (deny rules, admin locks). Böckeler's grid adds timing: a *guide* shapes the work before it happens, a *sensor* checks it after ([Böckeler](../../research/sources/fowler-bockeler-harness-engineering.md) independent). Hooks have both (PreToolUse, PostToolUse); OpenAI guardrails run in parallel by default and block only when told to; LangGraph says to put non-idempotent side effects after the interrupt. **Fail-open is the default everywhere:** hooks block only on exit 2 or `onFailure: block`, a timed-out hook lets the call through, `canUseTool` checks are silently bypassed for auto-approved tools ([hooks reference](../../research/sources/anthropic-claude-code-hooks-reference.md), [Agent SDK permissions](../../research/sources/anthropic-agent-sdk-permissions.md), [guardrails](../../research/sources/openai-agents-sdk-guardrails.md), [LangGraph interrupts](../../research/sources/langchain-langgraph-interrupts.md): first-party). This matches the existing theme `policy-enforcement-fail-open`.
- **Judge.** Script or schema → model in the same context (self-critique) → model in a fresh context (reader test, adversarial reviewer, isolated grader) → human. Vendors agree on the order: code "where possible", model "where necessary", human "sparingly for validation" ([evals post](../../research/sources/anthropic-demystifying-evals-ai-agents.md), [OpenAI graders](../../research/sources/openai-graders-guide.md): first-party). The fresh-context judge is increasingly the gate for judgment-heavy documents: doc-coauthoring's no-context reader test, Superpowers' subagent that reviews a design "as a builder would", Osmani's reviewer "biased to disprove", skill-creator's blind comparator ([doc-coauthoring](../../research/sources/anthropics-skills-doc-coauthoring.md) first-party; [Superpowers](../../research/sources/obra-superpowers-skills.md), [Osmani](../../research/sources/addyosmani-agent-skills.md) anecdote). Claude Managed Agents now ship this as a primitive: an "outcome" runs a grader in a separate context against a per-criterion rubric with an iteration cap, and the docs say to derive the rubric from a known-good example if you have none ([define outcomes](../../research/sources/anthropic-managed-agents-define-outcomes.md) first-party, beta).
- **Judge hygiene.** Model judges have four documented biases with procedural fixes: position (swap order, a flip is a tie), verbosity (length-controlled scoring raised one benchmark's correlation from 0.94 to 0.98), self-preference (use a different model family), weak reasoning grading (give a reference answer); an instability score across orderings can route only unstable verdicts to a human ([Zheng](../../research/sources/arxiv-zheng-judging-llm-as-a-judge.md), [length-controlled](../../research/sources/arxiv-length-controlled-alpacaeval.md), [self-preference](../../research/sources/arxiv-llm-evaluators-favor-own-generations.md), [not fair evaluators](../../research/sources/arxiv-llms-are-not-fair-evaluators.md): independent).

**Who triggers the human gate.** In every shipped system code decides when a human steps in, keyed to the kind of action (writes, not reads), an iteration cap, or a risk category, not to the model's confidence. Devin rates itself green/yellow/red and asks below green; Ramp chose Approve / Reject / Needs review over confidence scores ([Devin](../../research/sources/cognition-devin-2-1-confidence.md) vendor claim; [Ramp](../../research/sources/ramp-builders-agents-users-can-trust.md) first-party). Shipped autonomy controls converge on three judges layered: deterministic rules, then a classifier model, then a human prompt, under a sandbox, with admin locks and a circuit breaker (Claude Code auto mode pauses after 3 consecutive or 20 total blocks) ([permission modes](../../research/sources/anthropic-claude-code-permission-modes-docs.md), [VS Code approvals](../../research/sources/vscode-copilot-agent-approvals-and-permissions.md): first-party).

**Verification cost belongs here.** A human gate is only a gate if the reviewer can verify: when checking is expensive people rationally stop doing it, so friction must be sloped to stakes and verification made cheap (point to the line and the source) ([Vasconcelos](../../research/sources/arxiv-vasconcelos-explanations-can-reduce-overreliance.md), [Fok and Weld](../../research/sources/arxiv-fok-weld-in-search-of-verifiability.md): independent). This is the mechanism behind the library's `verification-capacity-gap` theme and Shopify's "slop grenades".

### C.3 Standard: the form of the bar

**Poles.** Checkable item (pass/fail) → criterion needing judgment (rubric) → exemplars and anti-exemplars → a stance (a way of working, enforced by the prompt) → taste left in the person. Two axes underneath: granularity of the statement, and how it is applied (summed item by item vs read holistically) ([Track B critique](scratch/track-b-standards-form-and-improvement.md)).

| Discipline rules | Mandatory invocation, an "iron law", a table rebutting the model's own excuses, pressure-scenario tests | Superpowers test-first skills | [Superpowers](../../research/sources/obra-superpowers-skills.md), [Vincent](../../research/sources/fsck-jesse-vincent-superpowers.md) anecdote |
| Stance as the standard | A prompt that enforces a way of working, not a property of the output ("give hints, never the answer") | GPT Tutor arm | [Bastani](../../research/sources/pnas-bastani-generative-ai-can-harm-learning.md) independent |
| Taste in the person | Criteria that need judgment and practice to apply; acquired by doing | Paul Graham's "Taste for Makers" | [Graham](../../research/sources/paulgraham-taste-for-makers.md) anecdote |

**Three findings that shape the choice.** First, *rules vs reasons tracks what is being protected*: content quality is encoded as reasons; disciplines the model is tempted to skip (test first, check for a skill, get approval) are made non-negotiable ([Track E](scratch/track-e-practitioner-skills-judgment.md), judgment reconciling first-party and anecdotal sources). Second, *the standard is discovered while grading*: Hamel's "criteria drift" (experts discover their standard as they grade) argues against writing a PM rubric up front; start from a few known-good examples and binary pass/fail with written critiques ([Hamel](../../research/sources/hamel-llm-as-judge-guide.md) independent). Third, *encoding costs expert hours and has a ceiling*: PaperBench rubrics took weeks per paper and HealthBench needed 262 physicians, and neither judge exceeded expert-expert agreement; Anthropic's response is "volume over quality: more automated checks with slightly lower signal" ([define success](../../research/sources/claude-platform-define-success-and-evaluations.md) first-party).

### C.4 Rights: who decides, who approves, who sets autonomy

**Poles.** Agent acts, human audits → agent acts inside bounds, human approves classes of action → agent proposes, human decides → agent informs, human does. Orthogonal to it: who sets the level (policy per task class; user slider; earned from measured accuracy; classifier) and separation of duties.

### C.5 Stance: how the skill treats the person's thinking

**Poles.** Do it → check it → challenge it (critique the human's work, or critique the other agent's output) → ask before (interrogate; the human commits first) → ask after (frame findings as questions) → coach (suggest the expert move to the human doing the work) → stay out. Track C's finding that matters most: the same information or model with a different stance produces different human outcomes, so this is a design lever, not a tone.

| Stance | Technique | Example | Evidence |
|---|---|---|---|
| Do | Produce the artifact from a template plus criteria; no questions beyond confirming the subject | PM write-spec; frontend-design | [PM plugin](../../research/sources/anthropics-kwp-pm-plugin-skills.md) first-party |
| Check | Self-critique against the brief in the same context; a fresh-context reader; a verification checklist | frontend-design; doc-coauthoring reader test; human-agent teams | [frontend-design](../../research/sources/anthropics-skills-frontend-design.md), [doc-coauthoring](../../research/sources/anthropics-skills-doc-coauthoring.md), [human-agent teams](../../research/sources/claude-building-effective-human-agent-teams.md) first-party |
| Challenge the human's work | Pre-mortem (assume failure, list causes); an independent second reader with standing and written answers to every objection; "challenge any requirement without evidence" | Klein's premortem; Amazon Bar Raiser; Ramp's seven shaping questions | [premortem](../../research/sources/hbr-klein-project-premortem.md) anecdote; [Bar Raiser](../../research/sources/metaview-bar-raiser-program.md) vendor claim; [Charles](../../research/sources/lenny-podcast-geoff-charles-product-when-coding-solved.md) first-party |
| Challenge the agent's output | An LLM devil's advocate arguing against the AI's recommendation; improved appropriate reliance at no perceived workload cost | Chiang et al. | [Chiang](../../research/sources/acm-chiang-llm-powered-devils-advocate-iui2024.md) independent, randomised |
| Ask before | One question at a time with a guess and a confidence attached; explicit-yes gate ("Sounds good" is not yes); required out-of-scope list; "never ask what you can read" | Osmani interview-me; Superpowers brainstorming; discernment-nudge's skip cases | [Osmani](../../research/sources/addyosmani-agent-skills.md), [Superpowers](../../research/sources/obra-superpowers-skills.md) anecdote; [discernment-nudge](../../research/sources/anthropics-skills-discernment-nudge.md) first-party |
| Ask after | Convert findings into questions; two or three specific follow-ups after a consequential answer, at most once per conversation | Danry et al.; discernment-nudge | [Danry](../../research/sources/acm-danry-dont-just-tell-me-ask-me-chi2023.md) independent; [discernment-nudge](../../research/sources/anthropics-skills-discernment-nudge.md) first-party |
| Withhold the answer | Hints and reasoning, never the solution, while the goal is learning; explanation without the recommendation | GPT Tutor; Gajos and Mamykina | [Bastani](../../research/sources/pnas-bastani-generative-ai-can-harm-learning.md), [Gajos](../../research/sources/arxiv-gajos-mamykina-ai-assistance-incidental-learning.md) independent |
| Coach | Real-time expert-move suggestions to the person doing the work; shifted tutors toward guiding questions, +4 points mastery, +9 for weaker tutors | Tutor CoPilot RCT (900 tutors) | [Tutor CoPilot](../../research/sources/arxiv-wang-tutor-copilot-rct.md) independent |

| Mixed initiative | Act when sure, ask when not, scope the service when in doubt; cheap invocation, dismissal and correction | Horvitz; Microsoft HAX | [Horvitz](../../research/sources/acm-horvitz-principles-of-mixed-initiative-user-interfaces.md), [HAX](../../research/sources/microsoft-hax-guidelines-for-human-ai-interaction.md) independent |

**Whose capability is the skill optimising?** The same skill cannot both maximise throughput and build the PM's judgment: Bastani's two arms demand opposite designs (deliver vs withhold). A skill should declare its job (produce, enforce, up-level) because the design choices are opposite ([Track C critique](scratch/track-c-human-judgment-cocreativity-overreliance.md), judgment on independent evidence). This is why the three jobs in section E map to different profiles rather than to points on one line.

### C.6 Record: what the skill leaves behind, and how it stays true

**Poles, by role rather than type.** An artifact can state the outcome (PRD, spec, prototype), record why (decision record, decision trace), track what is open (assumption register, open questions, elicitations), or state what done means (definition of done, checklist, required checks). The same document is often two of these at once: a PR/FAQ or design doc is the end product and the record of its review ([Track D critique](scratch/track-d-process-artifacts-multiparty.md)).

| Role | Technique | Example | Evidence |

**Freshness and fidelity are the two failure modes.** Stale records mislead agents (section A, point 9), so a standing artifact needs a way to stay true: immutable plus supersede, generated views, drift checks, a scheduled revisit (Google's "revisit in a year"), lint rules derived from decisions. And a record of work is not the work: the Ontario checklist result and MAST's verification failures both say that something must check the behaviour the artifact demands actually happened, beyond its ticks ([Urbach](../../research/sources/nejm-urbach-ontario-surgical-checklists.md), [MAST](../../research/sources/arxiv-why-multi-agent-llm-systems-fail.md) independent). The strongest quantified evidence for process structure in multi-agent work is modest and from code: MetaGPT's structured PRD → design → tasks handoffs scored 4.0 for executability against 1.0 for a lone agent; clearer role specs gave +9.4% and an objective-level verification step +15.6% in MAST's interventions ([MetaGPT](../../research/sources/arxiv-metagpt.md), [MAST](../../research/sources/arxiv-why-multi-agent-llm-systems-fail.md) independent).

### C.7 Loop: how the skill improves

Two axes, not one: **who writes the change** (human; agent proposes, human approves; agent alone) and **what signal drives it** (execution or metric feedback; an eval set; human corrections; the model's own judgment). Failure modes attach to each independently: self-curation persists errors (signal), whole-file rewrites collapse context (write method) ([Track B critique](scratch/track-b-standards-form-and-improvement.md)).

**Reading.** Loops improve in proportion to the honesty of the feedback signal; prose diagnosis is a better signal than a scalar score (GEPA; Warp's "the explanation of why is what makes feedback usable"); shipped products keep a human in the curate step. Two things the evidence keeps apart: the run-level loop ("iterate until the gate passes", a Stop hook or an outcome's iteration cap) and the skill-level loop (the skill gets better across runs). And re-test when models change, because "old guardrails may constrain smarter models" ([human-agent teams](../../research/sources/claude-building-effective-human-agent-teams.md) first-party), which is the decay point from the runtime synthesis restated.

## D. Two modifiers

**Party count.** A long-running session with several people and agents does not add techniques; it raises the weight of the Check and Record dimensions. The failure modes it adds are claimed-but-not-done work (agent-teams status lag; checklists "documented as complete"), clarification never asked (6.8% of MAST failures), and records drifting as contributors rotate (Nygard's original motive). Adding an adversarial agent aimed at the first agent is cheap and improves reliance; adding a human to a decision the AI does better degrades it ([Chiang](../../research/sources/acm-chiang-llm-powered-devils-advocate-iui2024.md), [Vaccaro](../../research/sources/arxiv-vaccaro-when-human-ai-combinations-are-useful.md) independent). Multi-party practice from the library: a written roster of human and agent roles, batched questions, caps on agent work per day so review stays sustainable and humans keep skills, a weekly lessons report ([human-agent teams](../../research/sources/claude-building-effective-human-agent-teams.md) first-party); public threads as "honesty pressure" and the smallest question an owner has to answer ([River](../../research/sources/x-tobi-river-reaction-to-shop-floor-post.md), [River remediation](../../research/sources/shopify-engineering-river-vulnerability-remediation.md) first-party).

**Competence fit.** Whether a task sits inside the model's competence, and whether the human alone beats the model alone, decides the right stance and rights for that step. Outside the frontier, more help made consultants worse and training made it worse still; inside it, help made everyone better and compressed the gap ([BCG](../../research/sources/bcg-how-people-create-and-destroy-value-with-gen-ai.md) independent). No static per-skill setting captures this; it is a per-task classification, and it moves with each model release (the runtime synthesis's decay point again).

## E. The three jobs mapped onto the dimensions

Geoff named three jobs for PM skills and agents: enforce standards, up-level the human's judgment and creativity, act autonomously where possible. They are not three points on a line; each is a profile across the seven dimensions, and the Stance choice for one is wrong for another.

| Dimension | Enforce standards | Up-level human judgment | Act autonomously |
|---|---|---|---|
| Path | Fixed stages, model fills content; the standard applied at a fixed pause point | Human-chosen or alternating; the agent never takes the pen on the decision | Code scaffold with model nodes; iteration cap; stopping condition |
| Check | Fail-closed hook on the process artifact (section present, owner named, record exists); fresh-context rubric grader on the content; code first, model second, human for calibration | Human is the judge; the agent lowers verification cost (point to the line and the source); forcing functions sloped to stakes | Script and schema checks before side effects; model grader with hygiene; human spot-check on a sample |
| Standard | Checkable items read holistically; a consensus filter separating settled from contested criteria; reasons attached; hard constraints short | Anti-exemplars and questions rather than positive exemplars (homogenisation); the standard discovered by grading with the team, not written up front | Exemplars and reference answers for the grader; thresholds with chosen numbers |
| Rights | Policy per task class; separation of duties (requester cannot approve); named human attests | Human decides; agent recommends or informs; declared "up-level" job, so it withholds | Earned autonomy from measured accuracy; tiered by environment; sandbox; circuit breaker |
| Stance | Check and challenge the work; challenge the other agent's output too | Ask before, ask after, coach; withhold the answer while the goal is learning; devil's advocate on the AI's recommendation | Do; ask only below a confidence category; batch questions |
| Record | Definition of done; required checks; drift checks on standing records | Open-question register; assumption map; pre-mortem; decision log with reasons; written answers to objections | Decision trace per action (inputs, policy version, approver); generated index of current records |
| Loop | Labelled samples graded by the standard owner; evals graduate into regression | A stance eval of its own ("did the human think"), not output quality; the team's grading sessions feed the rubric | Execution and metric feedback; eval set; re-test on each model release |

Evidence quality per job (judgment): enforce standards rests on independent assessment and judge research plus first-party harness docs; up-level rests on randomised studies from education and decision support, none in product work; act autonomously rests on first-party engineering accounts (Stripe, Ramp, Shopify, Cloudflare) and one independent production survey, none of them PM.

## F. References and artifact procedures

the project's description had two mechanisms: rich references the agent draws on, and encoded procedures for building artifacts, some end-product (a PRD) and some process (checklists, context graphs). The evidence refines both.

**References.** A reference library is where the standard lives when it is too large for the skill: Vercel's thin skills fetch a centrally owned rule list at run time; Osmani's CONSTRAINTS.md holds the numbers and a diff watch flags a weakened bar; Shopify's World monorepo holds skills, conventions, intent documents and runbooks that sessions add to ([Vercel skills](../../research/sources/vercel-labs-agent-skills-repo.md) first-party; [Osmani](../../research/sources/addyosmani-agent-skills.md) anecdote; [Under the River](../../research/sources/shopify-engineering-under-the-river.md) first-party). Three cautions from the evidence: references are what makes a model judge reliable (reference-guided grading), so they belong next to the gate as much as next to the author; positive exemplars converge output, so a reference library for taste should lean on anti-exemplars and forced choices; and a standing reference decays, so it needs the Record dimension's freshness techniques (an owner, supersede rather than edit, a generated index). Geoff's context repo ("evidence, not yet fact", a domain owner per topic, every spec writes its evidence back, [Intent Factory](../../research/sources/geoff-building-accelerating-intent-factory.md) first-party proposal) is the PM version of this layer, and the stale-records finding is the strongest argument for its owner-per-topic rule.

**Artifact procedures.** The procedures that work pair a fixed ritual with open content: PR/FAQ, design doc, premortem, spec toolchains. The fixed part is where deterministic checks attach (the section exists, alternatives are listed, an owner is named, the record is current); the open part is where judgment and the human's thinking live. Two implications for a PM skill that "builds a PRD": the skill's checkable layer is the process artifact around the PRD (open questions with owners, decisions with reasons, a definition of ready), and its judgment layer is the content, graded holistically against criteria the team discovered by grading its own past specs. The end-product artifact and the process artifact are not two kinds of skill; they are two layers of one, each with its own Check and Record settings.

## G. Worked example: an intent-shaping skill on each dimension

Geoff's two documents describe a shaping skill (standard questions, a named source per answer, every answer written back) and a risk advisor that classifies a spec against a known taxonomy ([Intent Factory](../../research/sources/geoff-building-accelerating-intent-factory.md), [Intent Shaping](../../research/sources/geoff-intent-shaping-well-managed-environment.md): first-party proposals). Placed on the seven dimensions, per step:

| Step of the skill | Path | Check | Standard | Rights | Stance | Record | Loop |
|---|---|---|---|---|---|---|---|
| Gather evidence (tickets, calls, code, wiki) | Model-chosen inside a code scaffold (parallel research streams, each writes a file) | Script: every claim has a source link; fail-closed | Checkable item | Agent acts | Do | Evidence files with sources | Execution feedback (link resolves) |
| Interrogate the PM (the seven questions) | Code-fixed question set; model-chosen follow-ups | Human is the judge; "needs evidence" stamp is a model check | Rubric with reasons; stance as the standard | Human decides; agent may not fill the answer | Ask before, one question at a time with a guess; challenge any requirement without evidence | Open-question register with owners and blocking flags | Stance eval: did the PM's answers change; team review of transcripts |
| Draft the short spec | Fixed template, model fills | Fresh-context reader test; completeness hook on required sections (fail-closed) | Checkable items read holistically; anti-exemplars for "reads well but says nothing" | Agent proposes, PM owns | Do, then self-check | The spec, plus decisions with reasons | Curated from PM corrections, agent proposes lines |

## H. Evidence quality, gaps and disagreements

**Strongest.** Randomised and peer-reviewed evidence on stance and over-reliance (Bastani, Danry, Chiang, Buçinca, Dell'Acqua, Vaccaro, Budzyń); the assessment literature on checklists vs rubrics (Ilgen) and surgical checklists (Haynes, Urbach); the model-judge literature (Zheng, TICK, Rubrics as Rewards); the homogenisation studies (Doshi and Hauser, Anderson, Padmakumar and He); the multi-agent failure taxonomy (MAST). None of it is about product work.

**Medium.** First-party harness documentation (hooks, permissions, guardrails, Managed Agents outcomes, Kiro, agent teams), which is precise about mechanism and silent on outcomes; first-party engineering accounts (Stripe, Shopify, Ramp, Cloudflare, Claude Code team) with self-reported numbers.

**Weak.** Practitioner anecdotes on decision records and skill wording (Davidson, Codeminer42, Superpowers, Osmani); the premortem's research base; the Bar Raiser as described by a vendor; "context graphs" as an investment thesis; checklist research read through abstracts.

**Gaps.** No comparison of code, model and human gates on error rates; no comparison of rule-heavy vs reason-heavy wording; no PM-domain study of rubric agreement with experienced PMs; no evidence that decision logs or context graphs improve agent decisions in PM work; no autonomy-drift data outside Claude Code; Socratic and critique stances untested on product decisions; no primary source found for the RAID log or Definition of Ready; several journal pages read via abstracts (flagged in each note).

**Disagreements worth keeping.** Anthropic's skill-creator calls all-caps MUSTs "a yellow flag" and its constitution argues rules generalise badly; Superpowers and Block argue for non-negotiable rules and explicit prohibitions. Both are first-party or anecdotal; the reconciliation in C.3 (reasons for quality, rules for disciplines the model skips) is this synthesis's judgment. Rubric research says decompose into checkable items; Hamel's criteria-drift finding says do not write the rubric up front. Both can hold: start from examples and binary grading, then write the items the grading reveals. Vendors say "human in the loop" as a safety floor; Vaccaro's meta-analysis says blended decisions average worse than the better party alone. The resolution is per task (comparative advantage), which is why competence fit is a modifier.

## I. Connection to existing work

- **Runtime taxonomy, work-structure and activity classification.** Track 6's eight axes (step predictability, verifiability, repeatability, error cost, audit, context breadth, collaboration, desired agency) describe the *work*; this document's seven dimensions describe the *skill's response*. The two tables join on the step: A2 verifiability sets which Check judge is feasible; A4 error cost and A5 audit set Rights and the Record's trace; A8 desired agency sets Stance; A3 repeatability sets whether a Standard is worth encoding at all (Ilgen: each task needs its own checklist). "Structure that decays vs structure the work demands" ([synthesis F.2](../research-agent-runtime-patterns-taxonomy/01-synthesis.md)) maps to Path (decays) against Check and Record (persist).
- **Tracks 4 and 6, skills and triggering.** A skill cannot enforce a gate; it inherits permissions. This document adds that the enforced gate is itself fail-open unless built otherwise, and that the fresh-context grader is now a harness primitive, which narrows the "when does a skill stop being enough" question in [capability-format-portability](../../options/DIMENSIONS.md#capability-format-portability-capability-format-and-portability).
- **PM-agents brief.** Its "bounded, context-fed, reviewable" jobs are the enforce and act profiles; its human-judgment jobs (strategy, prioritisation) are where the up-level profile applies, and where the evidence says a produce-stance skill would deskill.

# Follow-up 6: enterprise "agent OS" and agent platform vendors

Filed by: research-runtime-patterns-follow-up-round, 2026-10-24. Builds on [Track 1](track-1-meta-harnesses.md), [Track 5](track-5-shared-persistent-sessions.md) and 01-synthesis.md B.2 P4/P5, D.2, D.8, D.9, D.20.

## Question and scope

**Question.** Which enterprise vendors sell a governed agent workspace or agent control plane for employees, the big-vendor version of what we called P5 ("org-deployed agent workspace", our coined term, Cloudflare OS as the example)? For each: what the "OS" actually provides (registry, identity, policy, audit, memory or knowledge graph, builder for non-engineers, BYO harness or model, coding-agent support), how it is deployed, whether it can host or govern a Claude Code- or Codex-style harness or only its own agent, regulated-industry features, pricing, customers, and any independent evidence. Also: what the market calls this category.

**Vendors covered (9 plus analysts).** Microsoft (Agent 365, Entra Agent ID), Google (Gemini Enterprise Agent Platform), AWS (Bedrock AgentCore), OpenAI (Frontier), ServiceNow (AI Control Tower, Action Fabric), Salesforce (Agentforce, MuleSoft Agent Fabric), Glean (Agents), Writer (AI HQ), Anthropic (Claude Enterprise as a governed platform). Analyst framing came from Forrester (public blogs) and Gartner (only through secondary summaries). **Left out:** Dust, Sana, Notion agents, Atlassian Rovo (existing notes cover it), IBM watsonx Orchestrate, Kore.ai, UiPath, Amazon Quick Suite. They were dropped to keep depth. Ramp's "custom agent OS" is the existing [Notion video](../../research/sources/notion-inside-ramps-custom-agent-os.md), which was not re-read.

**Where I looked.** Vendor product pages, docs and blogs; trade press (The Decoder, TechInformed, CX Today, diginomica, CMSWire, Salesforce Ben); Forrester blogs; a Gartner summary on The Hacker News; independent security write-ups (Compass Security); customer pages (Syracuse University ITS, GitLab Handbook); one practitioner tutorial (Classmethod).

## Findings

**Bottom line**
- **The market term is "agent control plane", not "agent OS".** Microsoft calls Agent 365 "the control plane". Forrester has defined an "agent control plane" category (three planes: build, orchestration, control) and is assessing about 33 vendors. Salesforce's Agent Fabric and ServiceNow's "AI Control Tower" use the same idea. "Agent OS" and "agentic OS" are marketing words (Salesforce's "operating system for humans and agents", Cloudflare OS, Ramp's "custom agent OS", Lyzr). No analyst uses them. Gartner's words are "guardian agents" and "agent washing" (all independent or vendor-claim, 2025-12 to 2026-10).
- **What these vendors sell comes in two shapes, and P5 covers only one.** (a) **Governance-only control planes** register, identify, police and audit agents that run elsewhere, and do not run loops. Examples: Agent 365 ("governs; it does not host or run agents"), ServiceNow AI Control Tower, MuleSoft Agent Fabric. (b) **Full-stack agent platforms** bundle a builder, runtime, memory, governance and an employee-facing app. Examples: Gemini Enterprise Agent Platform, OpenAI Frontier, AWS AgentCore (no employee app read), Glean, Writer, Agentforce. Shape (b) is P5 at enterprise scale. Shape (a) is not P4 or P5: it is a separate class.
- **None of them wraps Claude Code or Codex the way a meta-harness does. Several can host or govern an agent built on the Claude Agent SDK.** Agent 365 onboards Claude Agent SDK agents through its SDK and CLI, and lists Claude Managed Agents as a preview registry-sync connector (first-party). AgentCore Runtime ran a Claude Agent SDK agent, which starts the Claude Code CLI as a subprocess (independent practitioner). ServiceNow lets Claude, with Cowork as the design partner, call governed workflows over MCP (vendor-claim). Glean uses Claude Code as a place to author its agents, not as a runtime it governs (vendor-claim). Local coding CLIs are at most *detected* (Defender Shadow AI, preview).
- **Independent evidence exists only on identity and audit, and it is cautionary.** Compass Security found that Entra Agent ID allowed 944 of 1,041 Graph permissions it tested, and that a blueprint owner could escalate to Global Administrator (independent, 2026-06-09). Syracuse University turned off Claude Cowork organisation-wide because it was not in audit logs (independent, 2026-02-20). Anthropic closed that gap on 2026-08-26 but still excludes Bedrock, Vertex and Foundry sessions (first-party). On adoption, Agentforce had about 12% of Salesforce customers with deals and about 6% paid (independent, 2026-02-23). No independent outcome data was found for any platform.
- **For a regulated build, the most concrete controls are at the tool boundary and in the audit feed, not in the "OS".** Examples: Cedar policies at AgentCore Gateway, evaluated outside the reasoning loop, with a log-only mode (vendor-claim). Compliance API session transcripts carrying verified user IDs (first-party). ServiceNow approvals reached over MCP (vendor-claim). An adopter (GitLab) reports that it is ownership and review, not platform toggles, that keeps a team's skills inside the team on Claude (first-party adopter).

### Cross-vendor observations
- **Agent identity is now table stakes, and no portable standard exists.** Every vendor gives each agent its own identity: Entra Agent ID, Google cryptographic IDs, Frontier, Glean (beta), AgentCore Identity. Forrester: "No such standard exists" for an agent identity that works across planes, and Entra's registry is proprietary. Standards decisions in the next 12-18 months could lock buyers into one vendor's identity model ([Forrester](../../research/sources/forrester-agent-control-planes-standards-stack.md), independent analyst).
- **Governance-only control planes depend on instrumentation.** Agent 365 shows only runs that emit a root `invoke_agent` span ([atlas](../../research/sources/microsoft-fasttrack-agent-365-lifecycle-atlas.md), first-party). Forrester: "A control plane can't govern what it can't observe" (independent analyst). So a Claude Code-based agent is governed by Agent 365 only to the extent we instrument and register it.
- **Audit coverage is per surface and per route, and it decides adoption in regulated settings.** Syracuse's turn-off of Cowork (independent) is the clearest case. The 2026-08 Compliance API extension still leaves out cloud-provider routes (first-party). So *where* the harness runs changes whose audit trail applies.
- **Deterministic enforcement is at the tool or action boundary.** Examples: AgentCore Policy at Gateway (vendor-claim), ServiceNow approvals over MCP (vendor-claim), Google semantic policies with dry-run (first-party release notes, snippet). Gartner's six delivery models for guardian agents include AI/MCP gateways (second-hand).
- **Platform-scoped governance versus owner-scoped governance.** GitLab maps one policy onto two platforms. Glean can enforce scoping by department, so a team's agents stay inside that team. Claude cannot, so ownership and git review hold the line ([GitLab](../../research/sources/gitlab-handbook-governance-platform-mapping.md), first-party adopter).
- **Adoption claims need the denominator.** The only independent adoption check (Agentforce, about 6% paid) is far below what the vendor headline suggests ([SF Ben](../../research/sources/salesforceben-agentforce-adoption.md), independent). Gartner's "agent washing" warning and its forecast that over 40% of agentic projects will be cancelled stand ([existing note](../../research/sources/gartner-agentic-ai-40-percent-cancelled.md), independent coverage); its guardian-agent guide reportedly calls current deployments "mainly prototypes or pilots" (second-hand).

## What changed for the taxonomy

1. **Split P5 by what the vendor runs.** Keep **P5 "org-deployed agent workspace" (our coined term)** for platforms that give employees a workspace running the platform's own agent. Cloudflare OS is the self-deployed, open-source example. Add the **vendor-hosted, full-stack enterprise agent platforms** as P5 examples: Gemini Enterprise Agent Platform with its app, OpenAI Frontier, Glean Agents, Writer AI HQ, Agentforce. The market term for these is **"agent platform"** or **"agentic AI platform"**, not "agent OS". Add a sub-axis to P5: *self-deployed in own cloud* (Cloudflare OS; AgentCore and Google in the customer's cloud account) versus *vendor SaaS* (Frontier, Glean, Writer, Agentforce).
2. **Add a new class, P11 "Agent control plane (governance-only)".** It is governance that sits outside build and runtime: registry, agent identity, access policy, observation, audit and intervention over agents that run elsewhere. It does not launch or wrap loops, so it is not P4, and it is not a workspace, so it is not P5. Examples: Microsoft Agent 365 plus Entra Agent ID, ServiceNow AI Control Tower, MuleSoft Agent Fabric. The full-stack platforms' govern pillars (Google Agent Registry and Gateway, AgentCore Policy) can also act this way for agents in their own cloud. **The term follows common usage** (Forrester category, Microsoft's self-description). Maturity: **early-adopter** for Agent 365 core (GA, priced, cheap per user, Microsoft estate). **Emerging** for cross-vendor reach (registry sync and Shadow AI in preview; Forrester says propagation across planes is "hand-built"). Gartner's "guardian agents" is the overlapping analyst term for the enforcement side.
3. **P4 (meta-harness) gets a sharper boundary.** None of the enterprise platforms is a meta-harness in the common horizontal sense. The nearest overlaps: (a) AgentCore Runtime hosting a Claude Agent SDK agent, which is P2 (vendor SDK embedded) running under a hyperscaler control plane; (b) Agent 365 registering Claude Managed Agents, which is P11 over P4's "model vendor's hosted service" shape. Record "Agent 365 governs Claude Code locally" as an unverified vendor-blog claim. The FastTrack atlas says only that Shadow AI detects local agents.
4. **Axis B.1 (governance and control).** Add a value, "external control plane (P11)", next to per-harness settings, gateway, and layer-launched policies. Note that it governs only what is instrumented and registered.
5. **Maturity (H.1).** Independent evidence for this whole class is three items: one security test (Compass on Entra), one customer turn-off (Syracuse on Cowork), and one adoption check (SF Ben on Agentforce). There is also one adopter-written configuration record (GitLab) and two public analyst blogs. No independent outcome or incident-reduction data exists for any platform.
6. **Terms.** Recommend that the strategy use **"agent control plane"** (P11) and **"enterprise agent platform"** (full-stack P5 variants) as the common terms. Keep **"org-deployed agent workspace"** as our coined term for the P5 pattern. Use "agent OS" only when quoting a vendor's product name.

## Proposed THEMES bullets

**New theme proposed: `agent-control-plane`: Agent control plane (registry, identity, policy, audit outside the runtime).** Governance that sits outside where agents are built and run: an inventory of the organisation's agents, an identity for each, access policy, observation, audit and intervention, across vendors. It matters because a regulated deployment of an intent-shaping agent will be governed by whatever control plane the company already runs (Microsoft, ServiceNow, AWS, Google), whichever harness we choose. *Why new:* `meta-harness` is about layers that launch or wrap harnesses. `identity-delegation` covers whose authority an agent uses, not inventory, policy or audit. `scoped-governance-containers` is about project or workspace scoping. None captures cross-vendor governance-only products, which Forrester and Microsoft name as their own category.

**Leans.** None. The evidence so far points to one thing that may matter: in a regulated company the *control plane* is likely already chosen by security and IT (Microsoft, ServiceNow or a cloud), and our harness choice would have to fit it.

# Track 2: Frameworks and SDKs for building your own harness

Date: 2026-10-24. Filed by: research-agent-runtime-patterns-taxonomy. Status: report for the director; menu of options and questions, not a recommendation. Source notes are in `../../research/sources/` (links below). Evidence labels: **first-party** (the builder describing its own product), **vendor claim**, **independent**, **anecdote**.

## 1. Headline findings

1. **Independent evidence is thin and mostly about coding agents.** The one systematic independent source, an arXiv source-code study of eleven coding harnesses, finds that none of them imports a general agent framework (LangChain, LangGraph, AutoGen, CrewAI, ADK, Pydantic AI, Semantic Kernel). The field runs on hand-rolled loops, and the harness SDKs (Claude Agent SDK, Codex SDK, OpenHands SDK) have become the "framework" layer ([arXiv study](../../research/sources/arxiv-harness-engineering-eleven-systems.md), independent). Its scope is coding; whether it holds for knowledge-work, multi-user, long-running agents is untested.
2. **Frameworks are converging toward harnesses.** LangChain now sells Deep Agents (harness), Microsoft Agent Framework ships a Harness Agent, Pydantic AI ships a Harness, and the Vercel AI SDK has a HarnessAgent that runs Claude Code, Codex or Pi. The framework / runtime / harness vocabulary is the vendors' own and admittedly fuzzy ([LangChain vocabulary](../../research/sources/langchain-agent-frameworks-runtimes-harnesses.md), vendor claim).
3. **Writing the loop is cheap; keeping it good is the cost.** A working agent is under 400 lines ([Amp](../../research/sources/ampcode-how-to-build-an-agent.md)); Mini-SWE-Agent's 50-line loop self-reports 74%+ on SWE-bench Verified (via the arXiv study). But Manus rebuilt its framework four times ([Manus](../../research/sources/manus-context-engineering-lessons.md)), Cognition rebuilt parts of Devin for one model ([Cognition](../../research/sources/cognition-devin-sonnet-45-rebuild.md)), and Anthropic says harness components encode assumptions that go stale as models improve ([Managed Agents](../../research/sources/anthropic-engineering-scaling-managed-agents.md), [harness design](../../research/sources/anthropic-harness-design-long-running-apps.md)). Evals are called the hardest problem by an independent practitioner ([Ronacher](../../research/sources/lucumr-agent-design-is-still-hard.md), anecdote).
4. **Even if the loop is bought, hosting is yours.** The Agent SDK spawns one CLI subprocess per session with state on local disk; sandboxing, session storage, tenant isolation and scaling are the builder's ([hosting guide](../../research/sources/anthropic-agent-sdk-hosting.md), first-party).
5. **Platform dependency is a real, documented cost.** Anthropic blocked subscription OAuth for third-party harnesses (January 2026) and says third-party products on the Agent SDK must use API keys ([VentureBeat](../../research/sources/venturebeat-anthropic-third-party-harness-crackdown.md), independent; [SDK overview](../../research/sources/anthropic-agent-sdk-overview.md), first-party; [Pi lock-out](../../research/sources/yage-pi-coding-agent-locked-out.md), anecdote).
6. **Evidence for building beyond Ramp is first-party and from large, engineering-heavy companies:** Stripe (forked Goose; [Minions](../../research/sources/stripe-minions-one-shot-coding-agents.md)), Cognition, Manus, Vercel, LangChain. No independent cost-of-ownership account (headcount, dollars, post-mortems of abandoned harnesses) was found after trying ten-plus routes; see section 7.

## 2. What a harness consists of

Working definition (independent, from the [arXiv study](../../research/sources/arxiv-harness-engineering-eleven-systems.md)): an agent is model plus harness, "a runtime the developer works inside of", as opposed to a framework which is a library you import. Seven subsystems, each with a minimal and a maximal observed form:

| Subsystem | Minimal (observed) | Maximal (observed) |
|---|---|---|
| Agent loop | linear while loop over one bash tool (Mini-SWE-Agent) | event-sourced conversation over a persistent log (OpenHands) |
| LLM integration | one LiteLLM call | five transports, 29 provider profiles (Hermes) |
| Tools and actions | bash only | 43 typed tools with deferred loading (Claude Code) |
| Memory and context | unbounded history | agent-maintained cross-session memory pipeline (Codex) |
| Safety and permissions | cost and step limits | policy rules, LLM approval reviewer, OS sandbox (Codex) |
| Orchestration | none (Aider) | recursive subagents (Claude Code); cross-vendor (Omnigent) |
| Extensibility | language protocols | marketplace-distributed plugins (Codex); everything-is-an-extension (Pi) |

Cross-cutting: interface layer (TUI, CLI, HTTP, SDK) and session substrate (transcripts, resume, fork). The task brief also lists **skills, hooks, observability, sandbox**: the study places skills/hooks under extensibility; sandbox under safety; observability is largely left to the builder (the Agent SDK inherits OpenTelemetry from the environment; [hosting](../../research/sources/anthropic-agent-sdk-hosting.md)).

Engineering guidance that recurs across Anthropic ([effective agents](../../research/sources/anthropic-building-effective-agents.md), [context engineering](../../research/sources/anthropic-effective-context-engineering.md), [long-running harnesses](../../research/sources/anthropic-effective-harnesses-long-running-agents.md)), Manus, Vercel and the study: start with one bash tool and a linear loop; keep prefixes stable for cache hit rate; use the filesystem as external memory; verify before stopping; add scaffolding only for observed failures; re-test it on each model.

Note a second meaning of "harness" in the evidence: OpenAI's "harness engineering" is the repository environment (docs, linters, layered architecture, observability) that lets agents work ([InfoQ summary](../../research/sources/infoq-openai-harness-engineering.md), vendor claim; OpenAI's own page returned 403).

## 4. Patterns on the taxonomy axes

- **Axis 2 (who owns the harness).** Five distinct postures appear: (a) use the vendor harness; (b) embed a harness SDK; (c) hosted harness (Managed Agents); (d) fork an open-source harness (Stripe on Goose; OpenClaw on Pi); (e) write a minimal own loop (Pi, Mini-SWE-Agent); plus (f) general framework for workflow-shaped agents, which the independent coding evidence does not support for coding but the framework vendors target for enterprise workflows. The hypothesis class (B) "own harness on a framework/SDK" should be **split** into harness-SDK embedding, framework-built, and open-source fork.
- **Axis 3 (coupling).** Provider coupling vs agnosticism is a measured trade-off: native harnesses exploit caching/thinking features; agnostic ones pay a maintained per-provider layer ([arXiv](../../research/sources/arxiv-harness-engineering-eleven-systems.md)). Access terms are a second coupling (subscription credit, API-key rules).
- **Axis 1 and 6 (runtime location, session persistence).** Vendor SDKs default to local disk and subprocess-per-session; the hosting guide's four patterns (ephemeral, long-running, hybrid with SessionStore, multi-agent container) are the clearest taxonomy of deployed session lifecycles found in Track 2. Anthropic's brain/hands/session split is the stated architecture for making harnesses replaceable.
- **Axis 8 (work structure).** Anthropic: workflows for predictable tasks, agents for open-ended; Microsoft: "if you can write a function ... do that"; Stripe wraps a Goose loop in deterministic steps (blueprint-like); Cognition argues against multi-agent crews for coding. Frameworks with explicit graphs (LangGraph, ADK, MAF workflows) fit the structured end; harness SDKs fit the open-ended end.
- **Axis 7 (governance).** Frameworks give hooks/middleware/guardrails; the control plane (identity, audit, spend) is mostly absent from the framework docs read, and is built by the adopter (Ramp LLM proxy; Stripe devbox isolation; Agent SDK egress-proxy and credential-proxy pattern in the hosting guide).

## 5. Build-vs-buy evidence

**For building / owning (all first-party or vendor claim unless noted):**
- Ramp's own reasons (moat, same-day fixes, learning for its product; already filed).
- Stripe: custom fork justified by a huge Ruby/Sorbet codebase, homegrown libraries, payments-critical stakes and existing human-oriented developer tooling; 1,000+ merged agent PRs per week (self-reported) ([Stripe](../../research/sources/stripe-minions-one-shot-coding-agents.md)).
- Control of context: Zechner built Pi because existing harnesses injected hidden context ([Pi](../../research/sources/mariozechner-pi-minimal-coding-agent.md), anecdote). Ronacher recommends owning the abstraction ([note](../../research/sources/lucumr-agent-design-is-still-hard.md), anecdote).
- Harness changes alone moved a fixed model from 52.8% to 66.5% (+13.7 points) on Terminal Bench 2.0 ([LangChain](../../research/sources/langchain-improving-deep-agents-harness-engineering.md), vendor claim, no independent replication).
- Simplifying a harness helped: Vercel d0, 80% to 100% on five queries ([Vercel](../../research/sources/vercel-we-removed-80-percent-of-our-agents-tools.md), first-party, tiny sample).
- Cost of the loop itself is low (Amp tutorial; Mini-SWE-Agent).

**Against building / for buying or reusing:**
- Upkeep: harness components go stale and get removed or rebuilt after model releases (Anthropic, Cognition, Manus). Anthropic's own long-task harness cost 20x a solo run on one task ($200 vs $9), so scaffolding is also a spend decision ([harness design](../../research/sources/anthropic-harness-design-long-running-apps.md)).
- Operational burden of a deployed harness is the builder's even with an SDK ([hosting](../../research/sources/anthropic-agent-sdk-hosting.md)); a hosted harness exists as the alternative but is beta with data-retention limits ([Managed Agents](../../research/sources/anthropic-managed-agents-overview.md)).
- Platform risk when building around a vendor's model access ([VentureBeat](../../research/sources/venturebeat-anthropic-third-party-harness-crackdown.md), independent).
- Framework churn: AutoGen archived with no fixes ([notice](../../research/sources/github-microsoft-autogen-archive-notice.md)); frameworks reposition every few months (LangChain family, Microsoft).
- Evals are the hard, unsolved part ([Ronacher](../../research/sources/lucumr-agent-design-is-still-hard.md)); harness tuning can overfit tasks ([LangChain](../../research/sources/langchain-improving-deep-agents-harness-engineering.md)).
- The independent study says the competitive unit is moving from the loop to the ecosystem surface (marketplaces, governance), which suggests the loop is a poor place to differentiate ([arXiv](../../research/sources/arxiv-harness-engineering-eleven-systems.md), independent; interpretive).
- Scale caveat: every build example is a well-resourced engineering organisation or an AI-product company.

**Mixed:** Anthropic itself both recommends starting with raw APIs and ships a framework-like SDK; its post says some tooling advice is outdated ([effective agents](../../research/sources/anthropic-building-effective-agents.md)). Cognition (don't build multi-agents) and Anthropic's multi-agent research system disagree ([Cognition](../../research/sources/cognition-dont-build-multi-agents.md)).

**Structural proposals for the director:** (1) split `harness-ownership` into the loop's *source* (vendor / SDK / framework / fork / own) and its *hosting* (local / self-hosted SDK / hosted), since runtime-location now overlaps; (2) keep `model-provider-coupling` separate from `harness-ownership` at first (different decision owner: procurement and vendor terms); (3) `harness-upkeep` is a resource-request dimension and could sit beside `investment-sequencing` and `adoption-model`; (4) `target-user` should carry whether users are builders (Ramp-like internal teams) or buyers of a harness, because all the build evidence comes from builders.

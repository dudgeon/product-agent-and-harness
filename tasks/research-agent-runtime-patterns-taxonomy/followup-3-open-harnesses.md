# Follow-up 3: open and third-party harnesses as loop sources or layers

Filed by research-runtime-patterns-follow-up-round, 2026-10-24. Builds on [Track 1](track-1-meta-harnesses.md) and [Track 2](track-2-harness-frameworks.md). This is a menu, not a recommendation. Evidence labels: first-party, vendor-claim, independent, anecdote. The field changes monthly, so dates are given.

## Question and scope

**Question.** Which other open or third-party harnesses could supply the loop (dimension `loop-source`) or sit as a layer (`harness-layering`) for an internal, regulated, mostly non-coding intent-shaping tool? For Superset, OpenCode, Goose, Cline (and Roo Code), Amp and Cursor: licence, governance, enterprise controls (SSO, audit, admin policy, self-hosting, model choice and BYOK, ZDR), support for skills, AGENTS.md and MCP, adoption signals, maturity and supplier risk, whether it can be forked, and whether it could be the base for a knowledge-work harness. Also Anthropic's restrictions on third-party clients.

**Where I looked.** GitHub repos and governance files (superset-sh/superset, aaif-goose/goose), vendor docs (opencode.ai, docs.cline.bot, cline.bot, ampcode.com, cursor.com, goose-docs.ai, superset.sh), the Thoughtworks Technology Radar, a consultancy radar (RUBINLAKE), analyst profiles (Ry Walker), Endor Labs' Agent Security League, an independent timeline of the Anthropic crackdown (falcao.org), the Show HN thread for Superset, and search summaries of The New Stack, The Information (via aggregators), CB Insights and others.

**Search terms used.** "Superset.sh parallel coding agents worktrees"; "OpenCode enterprise SSO self-host Anthropic OAuth removed 2026"; "goose Agentic AI Foundation governance 2026 enterprise"; "Why Block handed Goose to the Linux Foundation"; "goose skills SKILL.md AGENTS.md recipes custom distribution"; "Cline Enterprise SSO audit logs self-hosted"; "Cline funding 2026"; "Cline OpenAI acqui-hire January 2026"; "Roo Code shutting down archived 2026"; "Amp Inc spun out Sourcegraph ad-supported free tier"; "ampcode enterprise SSO zero data retention"; "Amp AGENTS.md skills MCP"; "Cursor run Claude Code inside Cursor third-party harness"; "Cursor SDK public beta April 2026"; "Cursor ACP"; "Cursor BYOK limitations ZDR SSO SCIM audit logs"; "Endor Labs benchmark harness"; "Thoughtworks Technology Radar OpenCode Goose Cline Amp"; "Anomaly opencode funding"; "OpenCode non-coding agent SDK server".

**Which Superset.** superset.sh (GitHub superset-sh/superset, Superset Inc.): a desktop app that runs many CLI coding agents in parallel git worktrees. It is not Apache Superset, the BI tool. HN commenters flagged the name clash, and the homepage says the product is "getting a new name soon" ([repo](../../research/sources/superset-sh-superset-repo.md), first-party; [site](../../research/sources/superset-sh-site-pricing-enterprise.md), vendor-claim).

## Findings

**Bottom line**
- **None of the six is a governance layer above Claude Code.** OpenCode, Goose, Cline, Amp and Cursor are each an alternative *loop source* (a harness of their own). Superset is a local parallel-session manager that is growing a hosted tier. For `harness-layering`, Superset adds evidence to the existing "local parallel-session manager" option and nothing to the governance-layer options.
- **Enterprise controls form a spectrum, and the closed products lead.** Cursor has the fullest documented admin model: SSO, SCIM, audit logs to a SIEM, enforced Privacy Mode with ZDR, model and MCP allowlists, fail-closed hooks. Amp has a SaaS posture (SOC 2 Type II, SSO, SCIM) but no self-hosting, and application audit logs are not shown to admins. Among the open harnesses, Cline has the most complete admin model: a hosted console, and transcripts written to the org's own S3 or R2 bucket for audit. But most of its controls bind only the VS Code and JetBrains extensions. OpenCode offers central config plus SSO that forces all traffic through the org's own gateway, and no audit feature. Goose has no admin plane: building one would be the distributor's job.
- **Goose is the most forkable base, and the only one built to be redistributed for non-coding audiences.** It is Apache-2.0, governed by the Linux Foundation's Agentic AI Foundation (AAIF) with merit-based maintainers, and has a documented custom-distribution path whose examples include a legal research assistant. Stripe forked it. OpenCode (MIT) and Cline (Apache-2.0 core) can also be forked, but each is owned by a small company. Amp and Cursor cannot be forked, though Cursor's SDK can be embedded as a model-agnostic loop. Superset's Elastic License 2.0 allows internal forks but not resale as a service.
- **Anthropic's crackdown restricts subscription credentials, not Claude itself.** Every one of these harnesses can still use Claude through API keys or a cloud provider. For internal tooling on company contracts it changes the cost comparison (flat-rate subscriptions only cover Claude Code and Claude.ai; the Agent SDK has capped credits from 2026-06-15), not whether it can be done ([falcao](../../research/sources/falcao-anthropic-claude-access-crackdown.md), independent, 2026-05-24).
- **Independent evidence remains thin, and none of it covers knowledge work.** Thoughtworks rates OpenCode Assess (2026-04) and rated Cline Trial (2025-04, since dropped from the radar); it has no Goose, Amp or Superset blip. Endor Labs' benchmark varies the harness with the model held fixed and finds small, inconsistent gaps (coding only). I found no independent evaluation of any of these harnesses on non-coding work.

### Superset
- **What it is.** Runs 21 named CLI agents (Claude Code, Codex, Cursor Agent, Gemini CLI, Copilot, OpenCode, Pi, Amp, Devin, Kiro and others) plus "any other CLI agent". Each task gets a git worktree, a branch and terminals. It ships an MCP server, built-in skills, remote hosts, automations, a CLI and a TypeScript SDK. Worktrees "do not sandbox processes or prevent merge conflicts" ([repo](../../research/sources/superset-sh-superset-repo.md), first-party, retrieved 2026-10-24).
- **Licence and supplier.** Elastic License 2.0: "The only thing off the table is repackaging Superset itself as a service you sell to others." The repo has about 15.5k stars and 548 open PRs. It is tagged YC-backed, and the product is about to be renamed (same note). The December 2025 Show HN called it open source; I could not confirm whether the licence changed since then.
- **Enterprise.** Pricing runs Free, Pro ($20), Team ($60, cloud workspaces in beta), Ultra ($200) and Enterprise (custom: SAML SSO, SCIM, audit logs, SOC 2 Type II report, SLA). "Superset never proxies model calls" and "agent sessions stay on your machine" ([site](../../research/sources/superset-sh-site-pricing-enterprise.md), vendor-claim). The governance it offers covers the account (identity, audit of the app), not what agents do. No named customers.
- **Independent view.** The Show HN drew about 96 points. Users praised it, but commenters said review is the bottleneck, called it "10x the cost with 0 to show", argued worktrees are the wrong primitive, and noted that databases and services are not isolated per worktree ([HN](../../research/sources/hn-superset-show-hn.md), anecdote, about Dec 2025). This matches Track 1's reading ([Franke](../../research/sources/garrit-meta-harness-parallel-agents.md), anecdote).
- **As a base for knowledge work.** Poor fit. It is a developer-throughput tool built around git worktrees.

### OpenCode
- **Enterprise offer.** A central config "can integrate with your SSO provider and ensures all users access only your internal AI gateway". "OpenCode does not store any of your code or context data". It supports private npm registries and per-seat pricing, and charges nothing for tokens when you bring your own gateway. Share pages should be disabled because self-hosted share pages are "on the roadmap". The page has no audit-log feature ([docs](../../research/sources/opencode-enterprise-docs.md), first-party, updated 2026-10-23). Audit in a regulated setting would have to come from the org's own gateway.
- **Risk view.** "most permissions default to allow"; plugins and custom tools "can execute arbitrary code"; remote MCP OAuth tokens are stored in a local file; "Do not standardize it until security and governance are explicit" ([RUBINLAKE](../../research/sources/rubinlake-radar-opencode.md), independent consultancy, 2026). Thoughtworks rates it Assess for its model flexibility, including air-gapped use, and warns users to understand provider terms ([Thoughtworks](../../research/sources/thoughtworks-radar-opencode.md), independent, 2026-04-15).
- **Supplier.** Owned by Anomaly (ex-SST), with undisclosed funding and young paid tiers (Go, Zen, Enterprise). The "7.5 million monthly developers" figure is company-claimed. There are reports of high RAM use and breaking releases ([Ry Walker](../../research/sources/rywalker-research-opencode.md), independent, mostly unsourced). The repo moved from sst to anomalyco ([repo](../../research/sources/github-opencode-repo.md), first-party).
- **Anthropic.** OpenCode removed Anthropic OAuth in PR #18186 on 2026-03-19, after legal demands ([falcao](../../research/sources/falcao-anthropic-claude-access-crackdown.md), independent). Claude through an API key or a gateway still works.
- **As a base.** OpenCode has a client/server design: `opencode serve` exposes an HTTP server with SSE streaming, there is an npm SDK, and third-party adapters (TanStack AI, Promptfoo) drive it. So it can be embedded as a loop without forking ([repo note follow-up](../../research/sources/github-opencode-repo.md); adapter docs seen only in search summaries). It is coding-oriented, and I found no non-coding fork.

### Goose
- **Governance.** "Founded by Block and now stewarded by AAIF", as a Series of LF Projects, LLC, which must approve governance changes. It has 3-7 Core Maintainers, majority votes when consensus fails, one week of review for major changes, and membership "tied to individual contributions, not employer affiliation". Bradley Axen is the named tie-breaker. The trademark owner is not stated ([goose repo follow-up](../../research/sources/github-block-goose-repo.md), first-party, retrieved 2026-10-24). The repo moved to the aaif-goose org (about 55.6k stars). According to search summaries of The New Stack (article body not fetched), Block's ownership of the trademarks and its opaque governance were the main obstacle to enterprise adoption, which the foundation was meant to remove.
- **Fork path.** CUSTOM_DISTROS.md covers presetting the provider and model (keys injected by MDM), bundling internal MCP servers, editing system prompts, branding, and recipes with sub-recipes and subagents. Its examples include a legal research assistant. It warns that "heavily diverged forks" are costly and miss security updates (same note). Stripe's Minions run on a Goose fork ([Stripe](../../research/sources/stripe-minions-one-shot-coding-agents.md), first-party).
- **Portability.** Reads SKILL.md from .agents/skills/ and from Claude Code's .claude/skills/ ([goose docs](../../research/sources/goose-docs-using-skills.md), first-party). It has 70+ MCP extensions and 15+ providers.
- **Enterprise controls.** None built in. SSO, audit and admin policy would be the distributor's job, which is what Stripe did with its own infrastructure. No independent review found beyond blog posts; Thoughtworks' current Tools quadrant has no Goose blip.
- **As a base for knowledge work.** It is a general agent, not coding-only, and non-coding distributions are an intended use, though the only example is hypothetical. Block's internal non-engineer use is first-party ([Lenny podcast](../../research/sources/lenny-podcast-block-dhanji-goose.md), first-party). Of the six, it fits a P3 fork of a knowledge-work harness best, at the cost of building the whole admin plane yourself.

### Cline (and Roo Code)
- **Enterprise.** Cline offers WorkOS SSO with IdP role mapping and JIT provisioning, a hosted admin console (app.cline.bot) that pushes provider, model, MCP, rules and skills policy, OTel export, and "prompt storage" that uploads full task transcripts (including file contents and command output) to the org's own S3 or R2 bucket "for compliance, audit trails". Enforcement is uneven: providers, MCP, skills and telemetry are enforced only in VS Code and JetBrains, and "The CLI and Cline Desktop don't enforce provider settings" ([docs](../../research/sources/cline-docs-enterprise-remote-configuration.md), first-party). The marketing page claims "VPC, on-prem, air-gapped" deployment with bring-your-own inference (same note). Samsung DX is the one named beta customer (2025).
- **Supplier.** Per The Information via aggregators, OpenAI hired at least seven Cline staff in January 2026. OpenAI said this was not an acquisition. CB Insights lists a "reverse acqui-hire" ([repo follow-up](../../research/sources/github-cline-repo.md); search summaries, unverified). Roo Code, the best-known Cline fork, shut down its extension, cloud and router on 2026-05-15 and pointed users to Cline and to its cloud-agent successor Roomote. A community fork, Zoo Code, reportedly continues (same note, secondary). Two lessons follow: forks of open harnesses also die, and core staff of a harness company can be hired away.
- **Independent view.** Thoughtworks rated it Trial in April 2025 as a "supervised" agent (Plan and Act); the blip is not on the current radar ([Thoughtworks](../../research/sources/thoughtworks-radar-cline.md), independent).
- **As a base.** The SDK (ClineCore, plugins, hooks, permission handling, "going to production" guide) makes Cline embeddable. It is coding-oriented. Its prompt-storage pattern is worth copying whatever harness is chosen.

### Amp
- **Posture.** SOC 2 Type II; SSO through WorkOS (can be the only login); SCIM; passkeys; "training can never be enabled" on Enterprise; "Minimal Data Retention". Admins see authentication-event logs, but application audit logs "are not exposed to admins". There is no self-hosting. Most inference goes to Anthropic, with OpenAI, Google, Bedrock and others also used ([security](../../research/sources/ampcode-security-reference.md), first-party).
- **Model stance.** "Amp uses them all, for what each model is best at." Per a third-party profile, users cannot pick models, and BYOK is limited to enterprise regional endpoints ([Ry Walker](../../research/sources/rywalker-research-amp-sourcegraph.md), independent, unsourced). Amp is multi-model, but the vendor makes the model choice, not the user.
- **Supplier and pricing.** Spun out of Sourcegraph in December 2025 (the corporate name differs between sources). The ad-supported free tier launched October 2025 and dropped ads around March 2026, while keeping roughly $10/day of free use. Paid use is pay-as-you-go at zero markup. All of this is second-hand (same note). Amp kills features it doesn't use ("If we don't use and love a feature, we kill it", manual), which counts against it as a stable dependency.
- **Skills.** Reads SKILL.md from .agents/skills and .claude/skills, and skills can bundle MCP servers (seen only in search summaries of Amp's skills page). Its role in AGENTS.md was not verified in this round.
- **As a base.** Cannot be forked or self-hosted. Amp's value for the project is as a reference for an opinionated, vendor-routed harness, and its 400-line agent tutorial is already filed ([Amp](../../research/sources/ampcode-how-to-build-an-agent.md), first-party).

### Cursor's stance on third-party harnesses
- **Exports its own harness rather than hosting others.** The Cursor SDK (public beta 2026-04-29) gives developers Cursor's harness (indexing, MCP, skills, hooks, subagents) locally, in a dedicated VM per agent on Cursor's cloud, or on self-hosted workers, "with any model supported in Cursor". It bills on token consumption. Use cases include internal GTM tools. Named customers: Faire, Rippling, Notion, C3 AI ([Cursor SDK](../../research/sources/cursor-sdk-typescript-launch.md), vendor-claim). The Cursor CLI can also be driven by other clients over ACP ("ACP enables Cursor's AI agent to work with editors beyond the Cursor desktop app"), but team-level MCP servers don't work in ACP mode ([ACP docs](../../research/sources/cursor-docs-cli-acp.md), first-party). Cloud agents are also reachable by API ([Cloud Agents API](../../research/sources/cursor-cloud-agents-api.md), vendor-claim).
- **Hosting Claude Code or Codex.** Because Cursor is a VS Code fork, Anthropic's Claude Code extension installs in it as a separate panel with its own context and billing (Anthropic docs and a DataCamp tutorial, April 2026, seen only in search summaries). I found no Cursor feature that runs Claude Code or Codex as a harness inside Cursor's own agent system. VS Code's own agents window does let users pick Copilot, Claude (Agent SDK) or Codex per session (search summary of an XDA review). So among editor vendors, Microsoft hosts other harnesses and Cursor exports its own.
- **BYOK limits.** "Custom API keys only work with chat models. Tab completion continues using Cursor's built-in models." "Cursor's Zero Data Retention policy does not apply when you use your own API keys." Teams and Enterprise pay a Cursor Token Rate of $0.25 per million tokens even on their own keys ([API keys](../../research/sources/cursor-docs-api-keys-byok.md), first-party). Cursor stays in both the data path and the billing path.
- **Admin controls.** SSO, SCIM, audit logs to SIEM, webhook or S3; org-enforced Privacy Mode; non-ZDR models need admin approval; MCP allowlist with per-tool restriction; hooks with failClosed; sandbox "Auto-review" with "a best-effort classifier" ([hardening](../../research/sources/cursor-docs-security-hardening.md), first-party).
- **Independent harness evidence.** Endor Labs' Agent Security League (built on CMU's SusVibes): Opus 4.7 scored 91.1% functional and 22.9% secure in Cursor, against 87.2% and 20.1% in Claude Code. With Opus 4.6, Claude Code was ahead on security (8.4 vs 7.8). The author treats a harness effect as a "hypothesis" and attributes small gaps to non-determinism ([Endor Labs](../../research/sources/endorlabs-agent-security-league-opus-4-7.md), independent, 2026-04-17). Secondary coverage claims GPT-5.5 scored 61.5% in Codex against 87.2% in Cursor; that is not in the post and unverified.

### Anthropic's restrictions on third-party clients (dated)
- 2026-01-09: server-side block on subscription OAuth outside Claude Code and Claude.ai (OpenCode, Cline, RooCode and OpenClaw affected). 2026-02-17 to 20: Consumer Terms updated. 2026-03-19: legal demands, and OpenCode removes Anthropic OAuth. 2026-04-04: Pro/Max stop covering third-party tools, with transition credits. 2026-05-13: "Agent SDK credits" announced, effective 2026-06-15, with programmatic use beyond the credits billed at API list prices. API keys were never blocked. OpenAI went the other way and extended Codex subscription support to OpenCode, OpenHands and RooCode (author's reading) ([falcao](../../research/sources/falcao-anthropic-claude-access-crackdown.md), independent, 2026-05-24; [VentureBeat follow-up](../../research/sources/venturebeat-anthropic-third-party-harness-crackdown.md), independent, 2026-01-09).
- **For this project.** A regulated internal tool would normally use company API, Bedrock or Vertex contracts anyway. The crackdown matters mainly when comparing per-seat subscription costs (Claude Code on a Max plan against an open harness on API rates) and as evidence that vendor access terms can change within weeks.

## What changed for the taxonomy

- **P3 (own harness: fork).** Split the fork option by who governs the upstream project: *foundation-governed* (Goose under AAIF/LF Projects, merit-based maintainers) versus *company-owned* (OpenCode by Anomaly, Cline by Cline Bot Inc.). Supplier risk differs: in 2026, a company-owned project lost staff to OpenAI (Cline), a fork shut down (Roo Code), and a project was forced to remove a provider integration after legal demands (OpenCode). Goose's custom-distribution path is the first documented, upstream-sanctioned route to a non-coding distribution, but it has no named example, so maturity stays "untested as a knowledge-work harness base".
- **P2 (vendor SDK embedded in an own product).** Add the Cursor SDK as a commercial embedded harness SDK that is *model-agnostic*. P2 is no longer single-provider by necessity: the Agent SDK is Claude-only, the Codex SDK is OpenAI-first, the Cursor SDK runs any Cursor-supported model. The cost is that Cursor sits in the data and billing path, with ZDR only on Cursor-routed models. Maturity: emerging (public beta 2026-04-29).
- **P4 local sub-shape (parallel-session managers).** These are drifting toward hosted products: Superset now sells cloud workspaces and an Enterprise tier with SSO, SCIM and audit. That governance covers the account, not the agents' actions, so the "no governance" description should become "account-level governance only, no policy over agent actions". The class is still developer-throughput tooling; maturity stays early-adopter.
- **Axis 7 (governance) and enterprise controls.** Add two concrete control points seen in open harnesses: (a) *gateway-only mode*: the harness is configured so every request goes through the org's own AI gateway, making the gateway the audit and policy point (OpenCode Enterprise); (b) *transcript export to org-owned storage* (Cline prompt storage). Both are cheap to copy in any harness choice.
- **Axis 3 (provider coupling).** Add a value: *vendor-routed multi-model harness*, where the harness vendor picks or routes the model and the user cannot, or can only within the vendor's routed set (Amp; Cursor partly). It differs from "provider-agnostic abstraction we maintain" because model choice and the data path stay with the vendor.
- **Terms.** No new terms coined. "Custom distribution" is goose's own term for a white-labelled fork and is used here as goose uses it. "Local parallel-session manager" stays a descriptive label (Track 1); practitioners call these "meta-harnesses", "orchestrators" or "IDEs for parallel agents".
- **Maturity ratings.** Open harnesses as coding loops: early-adopter, unchanged. Open harnesses as a regulated knowledge-work base: untested (no example found). Commercial embeddable SDK (Cursor): emerging.

### Proposed new theme: enterprise-admin-controls (justification)
No existing theme collects the admin controls a regulated buyer checks across harnesses: SSO, SCIM, audit logs and their scope, admin allowlists for models and MCP, ZDR scope, self-hosting, and whether controls bind every surface (IDE, CLI, desktop). `scoped-governance-containers` is about governance scoped to a project or workspace, and `identity-delegation` is about on-behalf-of identity; neither is about admin-control parity. Proposed header and description:

`## enterprise-admin-controls: Enterprise admin controls across harnesses`
Which identity, audit, policy and data-retention controls a harness gives an org admin, and on which surfaces they are enforced; a gating criterion in regulated settings.
- [Security and Privacy Hardening (Cursor enterprise docs)](sources/cursor-docs-security-hardening.md): fullest documented set: SSO, SCIM, SIEM audit, enforced Privacy Mode, model and MCP allowlists, failClosed hooks (research-runtime-patterns-follow-up-round)
- [Cline Enterprise remote configuration](sources/cline-docs-enterprise-remote-configuration.md): hosted console; controls bind VS Code and JetBrains only, not the CLI or desktop; transcripts to own bucket (research-runtime-patterns-follow-up-round)
- [Amp Security Reference](sources/ampcode-security-reference.md): auth-event logs only for admins; app logs on request (research-runtime-patterns-follow-up-round)
- [OpenCode Enterprise (docs)](sources/opencode-enterprise-docs.md): gateway-only config via SSO; no audit feature (research-runtime-patterns-follow-up-round)
- [Superset homepage, pricing and enterprise pages](sources/superset-sh-site-pricing-enterprise.md): SSO, SCIM and audit only on Enterprise (research-runtime-patterns-follow-up-round)

A second candidate, *harness-supplier-risk* (Vibe Kanban shutdown, Roo Code shutdown, Cline staff to OpenAI, Superset rename, Amp spinout, OpenCode's forced removal), could be folded into `build-vs-buy` instead; the coordinator should decide.

# Follow-up 4: Codex and Copilot enterprise and admin controls

Filed by research-runtime-patterns-follow-up-round, 2026-10-24. Topic: enterprise and admin controls for OpenAI Codex (CLI, IDE, desktop, cloud, Codex in ChatGPT Enterprise/Business) and GitHub Copilot (Business/Enterprise, cloud agent, partner agents), compared with Claude Code where useful. Thin spot named in [01-synthesis.md](01-synthesis.md) section I Q15 ("Codex and Copilot admin controls") and in [capability-distribution-trust](../../options/DIMENSIONS.md#capability-distribution-trust-capability-distribution-and-trust) key question 6 ("vendor trial of Codex/Copilot admin controls (not researched here)").

## Question and scope

**Looked for.** What a central owner in a regulated organisation can enforce, observe and pay for in Codex and Copilot today: managed configuration and its enforcement points; RBAC and workspace roles; audit and compliance logging (what is captured, for how long, with what identity fields); data retention, ZDR and residency; non-human identities; network/sandbox policy for cloud tasks; plugin, skill, custom-agent and MCP distribution and allowlisting; usage analytics and cost controls; content exclusion; partner agents (Claude, Codex) inside Copilot; and independent critiques of gaps.

**Where.** OpenAI's docs (now served at learn.chatgpt.com; developers.openai.com/codex/* 308-redirects there), help.openai.com (403 on the Compliance Platform article), docs.github.com, github.blog/changelog, plus independent writing (WorkOS, HIT Consultant, PromptArmor, SenseOn, Daniel Vaughan, an enterprise admin's public change log). Anthropic was only compared, from existing notes plus one follow-up read of the Claude Code MCP page.

## Findings

**Bottom line.**
- All three vendors now ship the same shape of local-harness policy: an admin-enforced file or cloud bundle that pins approvals/permissions, sandbox, network, MCP allowlist, hooks and plugin marketplaces, delivered by cloud per user or group, or by MDM. Copilot's `managed-settings.json` even reuses Claude Code's key names (`enabledPlugins`, `strictKnownMarketplaces`, `allowedMcpServers`, `permissions.deny/ask/allow`). The vocabulary is converging; the files, enforcement points and audit streams are not shared ([Copilot managed settings](../../research/sources/github-copilot-enterprise-managed-settings.md), first-party, 2026-08-06; [Codex managed configuration](../../research/sources/openai-codex-managed-configuration.md), first-party, undated).
- GitHub is the only vendor with a console that governs **several vendors' agents** (Copilot cloud agent plus Claude and Codex as partner agents) with per-agent policy, session search, enterprise custom agents and an agent-attribution audit schema (`actor_is_agent`, `agent_session_id`, initiating `user`; 180 days; SIEM streaming). It stops at GitHub.com: "Agents running in Visual Studio Code are not managed through GitHub at all" ([agent management](../../research/sources/github-copilot-agent-management.md), first-party, GA 2026-02-26; [audit events](../../research/sources/github-copilot-agentic-audit-log-events.md), first-party).
- Audit is the weakest link for a regulated setting in all three. Prompts and local actions are not in GitHub's audit log; OpenAI's Compliance API covers ChatGPT-authenticated Codex only, keeps 30 days and says conversation visibility "does not establish a complete record of local actions"; content capture in OTel is opt-in everywhere. No log correlates one identity across tools ([admin setup/governance](../../research/sources/openai-codex-enterprise-admin-setup.md), first-party; [Vaughan](../../research/sources/danielvaughan-codex-enterprise-analytics-compliance.md), independent, 2026-05-11; [SenseOn](../../research/sources/senseon-what-ai-coding-tools-log.md), independent with commercial interest, 2026-08-31).
- Regulated-data terms attach to surfaces and contracts, not products. Cloud agents are the usual exclusion: OpenAI says local-with-Work-Cloud is not strict ZDR; an independent healthcare engineer says Codex cloud is incompatible with ZDR; Claude Code cloud sessions are excluded for ZDR/HIPAA/CMEK ([HIT Consultant](../../research/sources/hitconsultant-ai-coding-tools-hipaa.md), independent, 2026-08-03).
- OpenAI now has a proper non-human identity for headless Codex: SCIM-provisioned service accounts whose tokens represent the account, with their own roles, groups, plugins and connections ([service accounts](../../research/sources/openai-codex-service-accounts-access-tokens.md), first-party, undated). Copilot's equivalent is the agent-as-GitHub-App with co-authored commits.

### Codex (Codex in ChatGPT Business/Enterprise)

- **Managed configuration** is now granular and centrally delivered: requirements vs defaults, cloud bundles targetable by user, group or role, and enforceable keys for approvals (including forcing automatic review), permission profiles, filesystem read denials, web search mode, command prefix rules, MCP identity matching, feature flags (hooks, browser use, computer use, apps, plugins), managed hooks, plugin marketplace sources and experimental network policy. Version floors matter (0.138.0 for permission profiles); hooks can fail open on error ([managed configuration](../../research/sources/openai-codex-managed-configuration.md), first-party, undated).
- **Surfaces are governed separately**: Codex local, Work local, Codex cloud (off by default for Enterprise), environment editing, connectors and reporting each have their own switch and owner; "Cloud environments don't inherit local device policy" ([admin setup](../../research/sources/openai-codex-enterprise-admin-setup.md), first-party).
- **Plugins** are a capability chain (package, skill controls, workspace app access, connector action control, the external service's IdP), with per-role Available/Installed. The public catalog can be exported for review, but workspace-created plugins are not in that export and no internal approval queue is documented ([plugin controls](../../research/sources/openai-codex-plugin-controls.md), first-party).
- **Cloud network**: agent phase off by default, GET/HEAD/OPTIONS-only option, but setup scripts always have internet and there is no documented egress log ([internet access](../../research/sources/openai-codex-cloud-internet-access.md), first-party; [WorkOS](../../research/sources/workos-agent-sandbox-egress-defaults.md), independent, 2026-09-15).
- **Identity**: SCIM service accounts with their own roles, plugins and connections; personal tokens with admin-set expiry limits; workspace UUID allowlist for login ([service accounts](../../research/sources/openai-codex-service-accounts-access-tokens.md), first-party).
- **Audit and retention**: Compliance API (`codex_log`, `conversation_message`) plus local OTel; 30-day retention; API-key Codex use is outside it ([governance](../../research/sources/openai-codex-enterprise-admin-setup.md), first-party; [Vaughan](../../research/sources/danielvaughan-codex-enterprise-analytics-compliance.md), independent).
- **Independent critique**: PromptArmor's disclosed exfiltration via email triage (2026-05-21) shows connector-reading agents leak through output rendering even with read-only use; a related macOS desktop CVE (2026-07-06) was seen only in search ([PromptArmor](../../research/sources/promptarmor-codex-for-everything-exfiltration.md), independent).

### Copilot (Business/Enterprise)

- **AI Controls / agent control plane** (GA 2026-02-26): per-agent policy (cloud agent in four states, partner agents separately), AI manager and custom roles, 24-hour session view with per-agent search, enterprise custom agents in `.github-private` protected by push rule ([agent management](../../research/sources/github-copilot-agent-management.md), first-party).
- **Client policy** via `managed-settings.json` (MCP allowlists GA 2026-08-06; sandbox floor; bypass lock; plugin marketplaces; OTel), enforced in the Copilot app, CLI and VS Code; the older registry-only MCP policy is preview, name-based and bypassable, and not supported for the cloud agent ([managed settings](../../research/sources/github-copilot-enterprise-managed-settings.md), first-party).
- **Cloud agent MCP is per repository or custom agent profile**, outside the private registry; the firewall does not cover MCP processes ([firewall](../../research/sources/github-copilot-cloud-agent-firewall.md), first-party).
- **Partner agents** (Claude, Codex) run under the same GitHub protections and billing, as GitHub Apps; how their prompts are retained by Anthropic/OpenAI is not stated ([third-party agents](../../research/sources/github-copilot-third-party-coding-agents.md), first-party).
- **Audit**: agent events carry `actor_is_agent`, `agent_session_id`, initiating `user`; 180 days; local prompts excluded; request/response bodies only in a preview stream for EMU or data-residency enterprises ([audit events](../../research/sources/github-copilot-agentic-audit-log-events.md), first-party).
- **Content exclusion** reached the CLI and app on 2026-09-02; VS Code agent mode still unsupported; cloud and partner agents not mentioned ([content exclusion](../../research/sources/github-copilot-content-exclusion.md), first-party).
- **Cost**: AI credits since 2026-06-01, pooled, budgets at three levels, no fallback model when exhausted ([billing](../../research/sources/github-blog-copilot-usage-based-billing.md), first-party, 2026-04-27). One enterprise admin's public log shows a universal 40,000-credit per-user monthly cap in July 2026 ([UMN DevEx](../../research/sources/umn-devex-github-copilot-changelog.md), anecdote).

### Independent evidence

Exists, but thin and narrow: WorkOS on egress defaults, HIT Consultant on ZDR/HIPAA, PromptArmor on an exfiltration chain, SenseOn on logging (vendor with an interest), Vaughan's practitioner series, one university admin log. **No independent hands-on evaluation of Codex managed configuration, Copilot AI Controls or partner-agent governance was found, and no admin forum thread on Copilot agent audit gaps was found.**

## What changed for the taxonomy

- **P1 (vendor harness plus skills):** the trade-off "skills are advisory and run with the host's permissions" stays, but the governance side of P1 is stronger than the synthesis implies. All three vendors now enforce approvals, sandbox floors, MCP allowlists and plugin sources centrally. Suggest adding to P1's trade-offs: "fleet policy is now vendor-native and fail-closed in all three major harnesses, but per vendor; audit of local sessions remains incomplete in all three." Maturity of the vendor admin layer: early-adopter to mainstream (GA features, few independent reports).
- **P4 (meta-harness):** GitHub AI Controls plus partner agents is a **vendor-hosted multi-vendor agent host**: one policy, audit and billing plane over Copilot, Claude and Codex loops, scoped to GitHub.com tasks. It fits the "hosted multi-harness control plane" sub-shape (with Warp Oz) and is the only one at GA from a large platform. This is the first mainstream-vendor instance of that sub-shape; it should be listed in P4 with the caveat that it governs only agents launched on GitHub.
- **P7 (background/cloud agents):** add as a cross-vendor regularity: cloud agents are the surface most often excluded from ZDR/HIPAA, and their egress controls have documented holes (Codex setup phase; Copilot MCP and setup steps).
- **P10 (portable skills/plugins):** the convergence of policy key names (Copilot copying Claude Code's) suggests "portable policy vocabulary" may follow "portable skill format". No standard exists; this is an observation, not a trend with evidence beyond one vendor.
- **Axis 7 (governance):** add "vendor-native admin policy (managed config, fail-closed cloud bundle)" as a distinct value from "per-harness settings": the seed row understates it.
- **Term:** "agent control plane" is GitHub's term for a console that governs agents across vendors; use it in that sense. "Agent HQ" and "mission control" were not found in the docs read.

Matters because it is the baseline a regulated owner compares any build or layer against.*

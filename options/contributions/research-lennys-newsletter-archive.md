## harness-layering: Is there a layer above the vendor harnesses

### New evidence for existing options
- **Hosted multi-harness control plane**: Warp's "software factory" adds triggers from Slack, Linear, GitHub and Sentry; issue to PR to computer-use QA video; every run recorded and scored; the factory definition is code edited by an observer agent — [warp-factory](../../research/sources/howiai-warp-zach-lloyd-software-factory.md) (vendor claim).
- **DIY coordinator calling harness CLIs** / **Stay in vendor harnesses, keep assets portable**: Mozilla's bug harness is a thin wrapper (v1 one prompt via `claude -p` or `codex exec`; v2 Agent SDK, about a dozen tools, a verifier); adding Codex because different model/harness pairs find different bugs — [mozilla](../../research/sources/howiai-mozilla-mythos-bug-harness.md) (first-party).
- **Meta-harness server above many harnesses (self-run)**: a mid-size company's own Go meta-harness orchestrates dozens of opencode sessions with plan/implement/review/QA roles, file-based handoff, TUI and headless CI modes — [cw-sharing-skills](../../research/sources/lenny-community-wisdom-sharing-skills.md) (anecdote; no write-up).

### Contradictions and cautions
- OpenAI's CPO advises against building scaffolding around current model limits, except for errors you can't tolerate — [weil](../../research/sources/lenny-podcast-kevin-weil-openai-cpo.md) (first-party); the same lab's Codex lead says model, API and harness must be co-designed — [embiricos](../../research/sources/lenny-podcast-embiricos-codex-human-bottleneck.md) (vendor claim).

### Key questions to add
None new; see cross-cutting Q2.

- **Status quo: scattered**: PMs hit chat upload limits and move to a coding agent over a folder; sharing context across the org is hard — [cw-pm-copilot](../../research/sources/lenny-community-wisdom-pm-copilot-context.md) (anecdote); no unified memory layer across assistants — [cw-fragmented](../../research/sources/lenny-community-wisdom-fragmented-ai-usage.md) (anecdote).

### Contradictions and cautions
- Curated vs connected: Notion's head of product says agents "don't really like walls" and a connected workspace is the context — [schoening](../../research/sources/lenny-podcast-max-schoening-agency.md) (vendor claim), against LinkedIn's curation result above; a Galileo engineer argues for being less precious about where information lives — [al-chen](../../research/sources/howiai-galileo-al-chen-codebase-context.md) (anecdote). Both could hold (connected but weighted).
- Vendors say generic memory should replace user-built "mind palaces" — [ambrosino](../../research/sources/lenny-podcast-ambrosino-codex-product-work.md), [sottiaux](../../research/sources/lenny-podcast-sottiaux-chatgpt-dots.md) (vendor claim).

### Key questions to add
1. Who keeps a PM harness's context current over months (the PM, the agent at session end, connectors, a scheduled pipeline), and what is the staleness under each? — *answered by:* a pilot measuring staleness of project knowledge per approach — *affects:* context-and-memory, harness-upkeep.
2. For shared metrics and definitions, do we route everyone through one gateway agent that owns the semantic layer, or give every agent an MCP server to the source of truth plus shared rules? — *answered by:* compare drift in answers to the same metric question across both set-ups — *affects:* context-and-memory, work-structure, governance-control-plane.
3. If memory stays local for privacy, how do scheduled or cloud runs reach it? (One PM runs workflows by hand because cloud schedules could not read local memory.) — *answered by:* runtime and memory-sync design — *affects:* context-and-memory, runtime-location, trust-privacy-defaults.

### New evidence for existing options
- **Output quality vs human baseline**: CASH scores each of four loop stages as an eval and hill-climbs them against a rough junior-PM win rate — [avasare](../../research/sources/lenny-podcast-amol-avasare-anthropic-growth.md) (first-party, no method published); a private senior-engineer benchmark (models about 30/100 until GPT 5.5 at about 62; human seniors high 80s to low 90s), with the caveat that benchmarks score already-framed problems — [shipper-paradox](../../research/sources/lenny-podcast-dan-shipper-ai-paradox.md) (anecdote); LLM judge calibrated to 10-100 human labels with a 90% agreement target — [khan](../../research/sources/lenny-newsletter-aman-khan-evals-guide.md) (vendor claim); a reference set of 20-100 input/output pairs plus review of the 20-50 worst cases per segment — [cc-cd](../../research/sources/lenny-newsletter-cc-cd-ai-lifecycle.md) (anecdote); "10 great evals" plus five trusted users' qualitative read — [cat-wu](../../research/sources/lenny-podcast-cat-wu-anthropic-product-team.md) (first-party); agents used as judges on 100 production traces missed failures needing product judgment and flagged good outputs, so agent-only grading is unsafe without human calibration — [advanced-evals](../../research/sources/lenny-newsletter-advanced-evals-error-discovery.md) (anecdote); quote verification (VERIFIED / PARAPHRASE / NOT FOUND) as a cheap gradeable eval for synthesis — [ai-analysis](../../research/sources/lenny-newsletter-ai-analysis-you-can-trust.md) (anecdote).
- **Delivery throughput**: Gusto measured PRs landed via DX (a designer at the 94th percentile; median review nine minutes) — [kim](../../research/sources/howiai-gusto-eddie-kim-cofounder.md) (first-party, self-reported); Coinbase cites PR review time cut from 150 to 15 hours across 1,000+ engineers — [coinbase](../../research/sources/howiai-coinbase-chintan-turakhia-ai-adoption.md) (first-party, show notes, method unknown); LinkedIn's org-level formula, experiment volume times quality over time to launch, no numbers yet — [cohen](../../research/sources/lenny-podcast-tomer-cohen-full-stack-builder.md) (first-party). Against: lines of code, significant lines and time-to-land all failed as measures at Anthropic — [fung](../../research/sources/lenny-podcast-fiona-fung-after-coding-solved.md) (first-party); a quoted Planview finding that enterprises could double dev teams with no appreciable business-outcome gain — [cw-discovery-big-org](../../research/sources/lenny-community-wisdom-discovery-big-org.md) (quoted third party, method not given); token leaderboards likened to counting lines of code — [graham](../../research/sources/lenny-podcast-molly-graham-delegating-to-ai.md) (anecdote); token spend as a vanity metric — [schoening](../../research/sources/lenny-podcast-max-schoening-agency.md) (vendor claim).
- **Usage and merge-share metrics**: Sendbird token tiers (kept out of performance review); Ramp power users at 5+ actions/week; Intercom merged PRs about 20% YoY; Shopify peer-rated AI use in reviews; all input or proxy measures — [sendbird](../../research/sources/howiai-sendbird-john-kim-adoption-playbook.md) (first-party), [25-tactics](../../research/sources/lenny-newsletter-25-ai-adoption-tactics.md) (anecdote). A cheap classifier over PRs and sessions by initiative shows where effort goes — [jev](../../research/sources/howiai-claire-vo-jev-decision-model.md) (anecdote).
- **Self-reported time saved** is biased: see the tech-workers survey above; Anthropic's CPO measures time saved on real work (a prototype in 20-25 minutes vs six hours) but calls it harder to quantify — [krieger](../../research/sources/lenny-podcast-mike-krieger-anthropic-cpo.md) (first-party).
- Experience quality beyond accuracy: swear words as a frustration proxy; per-team "bad" (unrecoverable) and "sad" (recoverable) events; verifying that the experience is what you wanted is unsolved — [fung](../../research/sources/lenny-podcast-fiona-fung-after-coding-solved.md) (first-party). Per-architecture agent metrics (automation rate, human review rate, cost per run) measure the agent, not PM outcomes — [three-agent-categories](../../research/sources/lenny-newsletter-three-agent-categories.md) (anecdote).

### Contradictions and cautions
- Evals catch only errors you already know about; Codex relies on regression evals plus A/B tests plus each engineer's hard problems — [reganti-badam](../../research/sources/lenny-podcast-reganti-badam-ai-deployments.md) (anecdote), against evals as "the defining skill" — [khan](../../research/sources/lenny-newsletter-aman-khan-evals-guide.md) (vendor claim). For a novel capability, start with open-ended testing and write evals once the use-case cluster is known — [liu](../../research/sources/lenny-podcast-howie-liu-airtable-reorg.md) (first-party); reconcilable with error analysis, since both say criteria come from looking at outputs first.

### Key questions to add
1. Who is the named expert who labels PM-agent output pass/fail, how much of their time can we fund, how many reviewed traces until the criteria stop moving, and which failure modes recur (invented decisions, wrong owners)? Coding agents may be a special case (developer as domain expert, constant dogfooding) — *answered by:* a two-week error-analysis pass on about 100 real outputs of one PM-agent job, with a PM as the labelling expert — *affects:* pm-agent-evaluation, review-and-autonomy, sequencing.
2. What crisp pass/fail signal exists for each candidate PM job (the equivalent of a sanitizer build), and which jobs have none? — *answered by:* a job-by-job inventory of verifiable signals — *affects:* pm-agent-evaluation, sequencing, review-and-autonomy.
3. Is draft retention (how much of an agent's PRD or brief survives review) a usable quality proxy, or does it reward bland drafts? — *answered by:* comparing retention against blind expert ratings on a sample — *affects:* pm-agent-evaluation, review-and-autonomy.

### Contradictions and cautions
- Knowledge-work output can't be verified like code; the agent must expose process, inputs and citations for the human to trust it — [seshan](../../research/sources/lenny-podcast-tara-seshan-persistent-coworkers.md) (first-party). Weakens automated verifiers for PM artifacts.
- Per-action approval is expected to fade; containment by permissions is the durable control — [schulhoff](../../research/sources/lenny-podcast-sander-schulhoff-ai-security.md) (independent); "click OK five times a minute" fails — [willison](../../research/sources/lenny-podcast-simon-willison-state-of-ai.md) (independent).
- Review hollowing and oversight load: "I just follow Claude" among surveyed workers — [tech-workers-2026](../../research/sources/lenny-newsletter-tech-workers-2026-survey.md) (anecdote within survey); the mental tax stays with the delegator and grows with agent count — [graham](../../research/sources/lenny-podcast-molly-graham-delegating-to-ai.md) (anecdote); verification is the ceiling, one engineer caps parallel agents at three — [cw-pms-coding-tools](../../research/sources/lenny-community-wisdom-pms-ai-coding-tools.md) (anecdote); PR, design review and QA became the bottleneck in a product-builder pilot — [cw-product-engineers](../../research/sources/lenny-community-wisdom-product-engineers-pilot.md) (anecdote); validation and review named as the current limit, with self-verifying agents as the fix — [embiricos](../../research/sources/lenny-podcast-embiricos-codex-human-bottleneck.md) (vendor claim).
- Review UI: approvals, a summarising inbox, logs and quick rollback when human and agent share an artifact — [shipper-paradox](../../research/sources/lenny-podcast-dan-shipper-ai-paradox.md) (anecdote); rendered preview before diff — [embiricos](../../research/sources/lenny-podcast-embiricos-codex-human-bottleneck.md) (vendor claim).

### Key questions to add
1. For PM artifacts with no executable test, what does the reviewer check (the output, the trace of inputs and reasoning, or both), what does showing the trace cost in reviewer time, and does an outcome-first review surface (rendered preview before diff) reduce it? — *answered by:* reviewer studies on agent-produced PM artifacts with and without traces; prototype review UIs — *affects:* review-and-autonomy, pm-agent-evaluation, agent-interface, trust-privacy-defaults.
2. Can a PM-written rubric plus subagent grader replace per-output human review for recurring jobs (changelogs, status, synthesis), and what false-pass rate is acceptable? — *answered by:* a pilot comparing rubric-graded outputs against human ratings on a held-out set — *affects:* review-and-autonomy, pm-agent-evaluation, sequencing.
3. When output volume rises, does human review stay real or become rubber-stamping? — *answered by:* time-per-review and defect escape before and after agent adoption on one team — *affects:* review-and-autonomy, pm-agent-evaluation.
4. Do encoded reviewer or persona critique agents change the spec before build, or only find what a later review would have found? — *answered by:* a pilot that runs them on live specs and logs which findings changed scope — *affects:* encoded reviewer pre-pass vs PM-led with a shaping skill.
5. Do we have permissions to let agents read the results of their own writes? (Companies reportedly grant write more readily than read, which stops agents checking their output.) — *answered by:* a permissions review of target systems (Slack, tracker, CRM) — *affects:* review-and-autonomy, agent-identity-delegation, governance-control-plane.
6. Must the reviewer of agent output be someone other than the person who prompted it? — *answered by:* audit and compliance requirements in the target enterprise; review-defect data — *affects:* review-and-autonomy, governance-control-plane.
See also cross-cutting Q1 (oversight capacity).

- Against prototype as spec: a prototype can't carry the why, constraints, edge cases or non-functional requirements — [cw-prototyping-vs-prds](../../research/sources/lenny-community-wisdom-prototyping-vs-prds.md) (anecdote); people interpret the same prototype differently — [cw-prototypes-release](../../research/sources/lenny-community-wisdom-prototypes-release-comms.md) (anecdote); AI prototype code is mostly useless to engineering unless built on real components and doesn't shorten 2-6 week timelines — [colin-matthews-team](../../research/sources/lenny-newsletter-colin-matthews-team-prototyping.md), [colin-matthews-brand](../../research/sources/howiai-colin-matthews-brand-prototypes.md) (anecdote); a design prototype handed to a coding agent reached 60-70% fidelity until every state was explicit and a screenshot check added — [cw-claude-design-handoff](../../research/sources/lenny-community-wisdom-claude-design-handoff.md) (anecdote); prototypes called "clickable PRDs, too immature" while engineers treat them as PRDs — [cw-non-pms](../../research/sources/lenny-community-wisdom-non-pms-shipping.md) (anecdote); the dominant real-world failure is not enough detail, and high-fidelity artifacts without engineering input blow out — [singer](../../research/sources/lenny-podcast-ryan-singer-shape-up.md) (anecdote); keep discovery prototypes flat — [margolis](../../research/sources/lenny-podcast-michael-margolis-bullseye.md) (anecdote); prototype-first teams insist review and engineering quality do not get cheaper; the last 10% is 90% of the work — [kim](../../research/sources/howiai-gusto-eddie-kim-cofounder.md), [schoening](../../research/sources/lenny-podcast-max-schoening-agency.md).
- Against spec-first: people can't specify complete requirements up front; criteria emerge from reviewing outputs — [evals-hamel-shreya](../../research/sources/lenny-newsletter-evals-hamel-shreya.md) (anecdote); Codex's lead doubts spec-driven development wins because people dislike writing specs — [embiricos](../../research/sources/lenny-podcast-embiricos-codex-human-bottleneck.md) (vendor claim); Penn's product is the model and her users are researchers, so eval-as-spec transfer is unproven.
- Prototype abundance: thousands of prototypes not aimed at an agreed problem — [stone](../../research/sources/lenny-podcast-elizabeth-stone-netflix-systems-thinkers.md) (first-party), [cw-am-calls](../../research/sources/lenny-community-wisdom-am-calls-mcp-server.md) (anecdote); coding tools are linear and bias to one direction, so divergent exploration still happens on a canvas first — [jenny-wen](../../research/sources/lenny-podcast-jenny-wen-design-process-dead.md) (first-party); a champion of three prototypes per feature has no confident way to choose among them and rejects simulated users — [willison](../../research/sources/lenny-podcast-simon-willison-state-of-ai.md) (independent).

### Key questions to add
1. When the receiver is a coding agent, which handoff form wins on downstream fidelity, review effort and rework: a document, a prototype plus a thin written delta or PR, or an eval set or goal with an executable check; what must the written layer still hold (why, constraints, edge cases, non-functional requirements, a verification section), and who writes it, PM or engineer? — *answered by:* a side-by-side of the forms on the same features; piloting a Notion-style verification section on PM-originated features and counting engineer rewrites — *affects:* all spec-standard options, review-and-autonomy, artifact-and-project-structure, pm-agent-evaluation.
2. Extending existing Q4 beyond prototypes: when the handoff is an eval set, a PR or a prototype rather than a document, who outside the team (risk, compliance, design) can read and sign it off, does it carry the why a regulated reviewer needs, and can a leader grant "no spec" permission at all or only a lighter approved artifact? — *answered by:* a spec-as-evals handoff with one risk reviewer on one feature; control-owner and sponsor interviews — *affects:* eval set as spec, PR as the PRD, prototype-first, adoption-model.
3. Should every intent artifact carry an explicit stage label (exploration, validated, ready to build), since prototype polish no longer signals that research or review happened? — *answered by:* review of how often polished prototypes are mistaken for decided work in pilot teams — *affects:* intent-shaping-and-spec, artifact-and-project-structure.
4. If the canonical spec is structured, can open questions be carried as a field with designed degraded states so delivery starts before every decision, which decision classes must close first in a regulated setting, and how do prose readers (risk, legal, executives) review: generated views or a separate prose artifact? — *answered by:* compliance and engineering leads reviewing 3-5 past initiatives; a trial with one reviewer group — *affects:* typed intent model, canonical spec plus risk mitigations, artifact-and-project-structure.
5. When prototypes are nearly free, what decides which of several variants proceeds, who decides and how fast, where are decisions logged, and can any of it be delegated (synthetic vs human usability signals)? — *answered by:* observing teams that prototype in parallel; a time study of decision latency; whether teams that gate prototyping on a framed problem ship fewer reworked features — *affects:* prototype-first, all shaping modes, sequencing, pm-agent-evaluation.
6. When building is nearly free, does shaping happen before the build (pitch, spec) or after it (build freely, decouple shipping from exposure, PM decides what to keep)? — *answered by:* trials comparing pre-build shaping with post-build triage on rework, bloat and maintenance cost — *affects:* intent-shaping-and-spec, review-and-autonomy, target-outcome.
7. How much spec detail does a coding agent need (is it set by the builder's capability, as Singer says for humans), and how do we keep agent-generated specs short enough for humans to read (12-page PRDs where 3 would do)? — *answered by:* matched tasks handed to agents at different spec depths; spec-length and reader-specific views in pilots — *affects:* intent-shaping-and-spec, work-structure, artifact-and-project-structure.
8. Should the canonical statement of intent be editable by agents at all? — *answered by:* whether teams that lock intent docs catch more code/intent drift than code-as-truth teams — *affects:* intent-shaping-and-spec, context-and-memory, review-and-autonomy.
9. Is the dependency and open-questions check a distinct agent job worth separating from drafting, or part of spec review? — *answered by:* comparing defect and rework rates with a separate checker agent vs a single drafting agent — *affects:* intent-shaping-and-spec, work-structure.

2. Should enablement start by giving each team the decision of what stays human, or by mandating use and measuring it? — *answered by:* a pilot comparing veto-style design sessions with a mandate, measuring sustained weekly use after 8-12 weeks — *affects:* adoption-model, activity-classification, review-and-autonomy.

## agent-interface: Agent interface: own app, chat, or embedded

### New evidence for existing options
- **Own app / workspace**: OpenAI tried Codex inside ChatGPT desktop and Atlas, but marketing, comms, finance and legal staff would not leave the Codex app despite code and command approvals; strategy became one app that starts simple — [ambrosino](../../research/sources/lenny-podcast-ambrosino-codex-product-work.md) (first-party); Grok Bot is a separate app rather than a tab in Cursor, internals hidden, automations in natural language — [ugarte](../../research/sources/lenny-podcast-roman-ugarte-grok-bot.md) (vendor claim); one box that chooses harness and model, with Work mode as Codex minus the coding UI — [seshan](../../research/sources/lenny-podcast-tara-seshan-persistent-coworkers.md) (first-party); Claude's multiple entry points exist because form factors are unsettled; the end state is probably one place — [rieseberg](../../research/sources/howiai-felix-rieseberg-cowork.md) (vendor claim).

- **Chat-native plus a companion web surface**: chat as the right catch-all with functional GUIs for experts — [weil](../../research/sources/lenny-podcast-kevin-weil-openai-cpo.md) (first-party), [embiricos](../../research/sources/lenny-podcast-embiricos-codex-human-bottleneck.md) (vendor claim); "chat is not the final boss" — [udezue](../../research/sources/lenny-podcast-udezue-ai-reshaping-pm-role.md) (anecdote).

### New options

### New evidence for existing options
- **Isolation by task context, not just user permission**: any data the AI can access, a user can make it leak; any action it can take, a user can make it take — [schulhoff](../../research/sources/lenny-podcast-sander-schulhoff-ai-security.md) (independent); ChatGPT Sites shows each viewer only the data their own connectors grant — [korevec](../../research/sources/howiai-openai-korevec-chatgpt-sites.md) (vendor claim).

- Lethal trifecta: any PM agent that reads untrusted text (customer email, tickets, forums) while holding private data and an outbound channel is exposed; filters at 97% are a failing grade; cut the exfiltration leg — [willison](../../research/sources/lenny-podcast-simon-willison-state-of-ai.md) (independent).

### Key questions to add
1. Which PM-agent jobs combine reading untrusted input (customer feedback, email, web pages) with write actions to shared systems, so task-scoped permissions alone cannot protect them? — *answered by:* a read/write map of the target PM jobs — *affects:* trust-privacy-defaults, governance-control-plane, sequencing.

## loop-source
- **Evidence row for "Fork or extend an open-source harness" (originator case):** Block built goose (open source, Apache-2.0) as its company-wide general agent, kept building on it after handing it to the Linux Foundation's AAIF (Dec 2025; repo moved 2026-04-07), and built Builderbot on it. It states its stance as "the models are interchangeable", with the harness, data and distribution its own. Maturity: early-adopter at Block's scale. Evidence: [Q2 2026 letter](../research/sources/block-q2-2026-shareholder-letter.md) (first-party); [goose moves to AAIF](../research/sources/goose-blog-moves-to-aaif.md) (first-party); [Builderbot](../research/sources/block-builderbot-rollout.md) (vendor claim).
- **New option candidate: "Own general harness for everyone, buy coding harnesses for engineers".** goose for every employee. Engineering buys seven coding harnesses ("We buy them all": Claude Code, goose, Cursor, Copilot, Cline, Amp, Firebender) and keeps them aligned through shared rules and skills. *Gives:* one integration surface for non-engineers, and best-of-breed tools for engineers. *Costs:* two loop sources to keep up, and configs that drift across seven harnesses (Block's answer is the `ai-rules` generator). Evidence: [AI-assisted development at Block](../research/sources/block-eng-ai-assisted-development-at-block.md) (first-party, 2026-01-18); [investor day](../research/sources/block-investor-day-2025-ai-engineering-transcript.md) (vendor claim). Close to "Two loop sources by work family"; the director may merge it there.
- Key question: if we fork goose (or any foundation-governed harness), how much of Block's value comes from goose itself, and how much from the ~150 internal MCP servers, the data layer and the distribution, none of which come with a fork? — *answered by:* an interview with Block's AI capabilities team; a trial goose distribution on 5 of our own MCP servers — *affects:* fork, embed SDK, hosted harness.

## harness-layering
- **Evidence row for "Stay in vendor harnesses, keep assets portable":** Block keeps rules, skills and context harness-neutral. It runs an internal skills marketplace (100+ SKILL.md skills with role bundles), uses AGENTS.md, and has an `ai-rules` generator that writes each harness's config from one rule set. Evidence: [AI-assisted dev](../research/sources/block-eng-ai-assisted-development-at-block.md); [3 principles for skills](../research/sources/block-eng-3-principles-agent-skills.md) (first-party).
- **Evidence row for "Shared live session over any harness":** Buzz (open source, July 2026) is a workspace where people and agents share channels. Any ACP agent (goose, Claude Code, Codex) can join, with its own keypair identity, so a team can switch harness without losing history. Maturity: emerging. Evidence: [Buzz](../research/sources/block-eng-buzz.md); [configuring agents in Buzz](../research/sources/block-eng-configuring-agents-in-buzz.md) (first-party).
- Key question: does a harness-neutral layer (shared skills plus a rules generator, or a Buzz-like workspace) cost less to run than standardising on one harness, once a team uses three or more? — *answered by:* Block's developer-experience team; our own count of harnesses in use — *affects:* stay-in-vendor, meta-harness, shared live session.

## model-provider-coupling
- **Evidence row for "Provider-agnostic abstraction we maintain":** Block serves Claude, GPT and Gemini through Databricks-hosted endpoints, and staff pick models by hand per task (engineers mostly Claude, marketing ChatGPT); local models are "a very small percentage". Evidence: [Chain of Thought, Angie Jones](../research/sources/chainofthought-angie-jones-block-goose-rollout.md); [How I AI](../research/sources/howiai-block-goose-brosamer-axen.md) (first-party).

## capability-format-portability
- **New option candidate: "Recipe as a parameterised task agent inside a general harness".** A goose recipe is a YAML file. It holds instructions, typed parameters, the extensions to load, model settings, sub-recipes, a JSON response schema and retries checked by shell commands. It can be shared by deep link, scheduled, or run as a subagent. *Gives:* task agents without a new runtime. *Costs:* a poisoned recipe was the winning attack in Block's own red-team exercise. Evidence: [goose recipes docs](../research/sources/goose-docs-recipes.md); [detection-engineering recipes](../research/sources/goose-blog-detection-engineering-panther-recipes.md); [red team](../research/sources/block-eng-red-teamed-own-ai-agent.md) (first-party). Close to "Packaged subagent definition"; differs in typed parameters, response schema and sharing by link.
- **Evidence for moving a capability between layers:** Block moved its internal app-publishing capability from an MCP server (BlockCell) to a distributed skill on a fixed stack (App Kit). Its stated rule: scripts own what must reproduce, skills own the procedure ("know what the agent should not decide"). Evidence: [App Kit](../research/sources/block-eng-app-kit-localhost-to-launched.md); [3 principles](../research/sources/block-eng-3-principles-agent-skills.md) (first-party). Theme: capability-packaging-layers.
- Key question: for each PM capability we'd package (data lookup, spec check, prototype publish), which layer should own it (MCP server, skill, recipe or platform service), and what makes it move between them? — *answered by:* a prototype that packages one capability two ways; Block's App Kit team — *affects:* all options here.

## capability-distribution-trust
- **Evidence row for "Curated internal MCP 'app store' with a security rubric":**
  - Block runs over 100 pre-approved internal MCP servers (about 150 services by November 2025), and goose gets a curated default bundle.
  - Even internally built servers need a security review before they join the allowlist.
  - The upstream allowlist is client-side and fails open: no variable means no restriction.
  - Evidence: [The New Stack](../research/sources/thenewstack-block-12000-employees-ai-agents.md) (independent, 2025-10-20); [Jones](../research/sources/chainofthought-angie-jones-block-goose-rollout.md); [extension allowlist docs](../research/sources/goose-docs-extension-allowlist.md) (first-party).
- **Evidence row for "Git-backed skills marketplace":** an internal marketplace of 100+ skills, PR-reviewed, with role bundles. Evidence: [3 principles](../research/sources/block-eng-3-principles-agent-skills.md) (first-party).
- Key question: who reviews a shared recipe or skill before others run it, given that Block's red team won with a poisoned recipe? — *answered by:* our security owner; Block's offensive security team — *affects:* registry gate, peer pass, curated store.

## governance-control-plane
- **Evidence row for "Tiered intake by use-case complexity":** Block's AI-integration review received "several hundred requests" and tiers its requirements by data-sensitivity level (DSL-1 to DSL-4). Evidence: [GenAI security principles](../research/sources/block-eng-genai-security-principles.md) (first-party).
- **Evidence row for "Deterministic gates in the harness":** Block proposes a "CORS for agents" control that gates chained tool calls in code, not by the model. goose's adversary-mode reviewer is off by default and fails open. Evidence: [guardrails](../research/sources/block-eng-agent-guardrails-and-controls.md); [adversary mode](../research/sources/goose-docs-adversary-mode.md) (first-party).
- Evidence for "no admin plane in the open harness": goose has no SSO, audit or admin console. Block distributes it through its internal software centre, with auto-update and preset servers and models. Evidence: [The New Stack](../research/sources/thenewstack-block-12000-employees-ai-agents.md) (independent).

## work-structure (agent-unit sub-choice)
- **Evidence row for "Hybrid": a general harness per person, plus shared stage services.**
  - Every employee gets goose (one general agent, many MCP servers).
  - The shared, heavy jobs became services built on it: Builderbot (ticket or thread to merged PR, ~15% of production changes, reviews 90%+ of change requests), and Query Expert and the Data MCP (2.1K monthly users).
  - Task agents inside goose are recipes and sub-recipes.
  - Evidence: [Builderbot](../research/sources/block-builderbot-rollout.md) (vendor claim); [Q1 2026 letter](../research/sources/block-q1-2026-shareholder-letter.md); [data foundation](../research/sources/block-eng-data-foundation-automated-analytics.md) (first-party).
- **Evidence against a "PM persona agent":** Block's leaders describe the PM role being folded into an IC builder role and a DRI who owns idea to scale, not a PM agent. No PM-specific goose recipe or agent was found; the public cookbook has none for PRDs, research or synthesis. Evidence: [From Hierarchy to Intelligence](../research/sources/block-from-hierarchy-to-intelligence.md); [Dorsey on Sequoia](../research/sources/sequoia-dorsey-every-company-mini-agi.md); [goose recipes](../research/sources/goose-docs-recipes.md) (first-party).
- Key question: at Block, are the shared services (Builderbot, Query Expert) what changed throughput, or the per-person harness? Block's own metrics mix both. — *answered by:* Block's AI capabilities team; our own pilot comparing the two — *affects:* general harness, hybrid, stage agent.

## intent-shaping-and-spec
- **Evidence row for "Prototype as spec" / "Prototype-first":** Dorsey says people now bring "a prototype that they built" instead of decks or Google Docs, a change he dates to about two months before the interview. Cash App design runs Friday demos, deleted design crits as an experiment, and says over 90% of designers ship production PRs. Evidence: [Dorsey on Sequoia](../research/sources/sequoia-dorsey-every-company-mini-agi.md) (first-party, ~2026-04-02); [Worboys](../research/sources/dive-club-cam-worboys-ai-native-design-org.md) (first-party, 2026-03-05).
- **Evidence row for "Agent-originated intent" (proposed, not shown):** Block's operating essay says that when the intelligence layer cannot compose a customer solution, "that failure signal is the future roadmap", and that customer reality generates the backlog. Maturity: stated plan. Evidence: [From Hierarchy to Intelligence](../research/sources/block-from-hierarchy-to-intelligence.md) (first-party, 2026-03-31).
- **Evidence row for "Spec pushed straight to coding agents":** Builderbot starts from a Slack thread with "a short description" or a Linear or Jira ticket. goose's own repo admits only "Ready" issues, with agreed design and verification, to agents. Evidence: [Builderbot](../research/sources/block-builderbot-rollout.md); [issues are the new PRs](../research/sources/goose-blog-issues-are-the-new-prs.md) (first-party).
- Key question: when the PM-shaped intent reaches Builderbot as a ticket or thread, what of the research and rationale goes with it? — *answered by:* a Block DRI or PM interview; three sample Builderbot threads — *affects:* prototype as spec, spec pushed to agents, committed artifact chain.

## session-persistence-sharing
- **Evidence row for "Ephemeral-private" plus a shared thread for execution:** goose sessions are local to a laptop (desktop or CLI). The shared, multi-person surface is the Slack thread in which teammates steer Builderbot. No source shows goose research sessions being handed between people. Evidence: [How I AI](../research/sources/howiai-block-goose-brosamer-axen.md); [Builderbot](../research/sources/block-builderbot-rollout.md).
- Key question: does Block share goose sessions internally (export, link, Buzz), or is the thread the only shared context? — *answered by:* Block's goose or Buzz team — *affects:* ephemeral-private, shared / multiplayer, message into a running session.

## agent-interface
- **Evidence row (two surfaces by job):** a desktop app and CLI for the general agent (goose). Slack and the ticketing tools (Linear, Jira) for the shared build service (Builderbot). Internal web apps published from agent sessions (App Kit, 1,000+ apps, ~80% of users outside engineering). MCP Apps render interactive UI inside goose's chat (experimental). Evidence: [App Kit](../research/sources/block-eng-app-kit-localhost-to-launched.md); [MCP Apps](../research/sources/goose-blog-mcp-apps.md); [Builderbot](../research/sources/block-builderbot-rollout.md) (first-party).

## context-and-memory
- **Evidence row for "Governed semantic layer with owned definitions":** Block's Data MCP exposes 1,100+ governed metrics, and Query Expert indexes ~10K heavily used tables and vetted queries. Both were built by a seven-person team in six weeks, and evals were iterated to 100% on priority questions. Evidence: [data foundation](../research/sources/block-eng-data-foundation-automated-analytics.md) (first-party, 2026-04-29).
- **Evidence row for "Shared plain-text context repo" (proposed):** Jennings describes the company as "a markdown file" of values, metrics and non-goals that agents iterate against. The essay proposes a company and customer "world model" built from remote-first work artifacts. Neither is shown in use. Evidence: [Jennings](../research/sources/a16z-owen-jennings-block-all-in-on-ai.md); [essay](../research/sources/block-from-hierarchy-to-intelligence.md) (first-party).

## review-and-autonomy
- **Evidence row for "Human review on every change" with an AI pre-pass:** AI reviewed 90%+ of change requests and makes ~15% of changes "nearly fully autonomously", while a human makes the final push decision (Q1 2026). Staff told the Guardian that all changes need human approval and that about 95% of AI changes needed edits (late 2025). goose's default permission mode is Autonomous. Evidence: [Q1 2026 letter](../research/sources/block-q1-2026-shareholder-letter.md) (first-party); [Guardian](../research/sources/guardian-block-workers-ai-cant-do-their-jobs.md) (independent); [permission modes](../research/sources/goose-docs-permission-modes.md) (first-party).
- **Evidence row for "Autonomy tiered by environment":** Jennings says human-in-the-loop is "critical" for regulators, and the cut left compliance "basically" untouched. Evidence: [Jennings](../research/sources/a16z-owen-jennings-block-all-in-on-ai.md) (first-party).

## adoption-model
- **Evidence row (distribution as enablement):** goose was auto-installed through the internal software centre, with preset servers and models. Help and inspiration Slack channels were "the best organic drivers of adoption". About 50 AI Champions spend 30% of their time on it. Leaders use goose daily. Claimed reach: about 12,000 employees in eight weeks (2025). Evidence: [The New Stack](../research/sources/thenewstack-block-12000-employees-ai-agents.md) (independent); [AI-assisted dev](../research/sources/block-eng-ai-assisted-development-at-block.md); [CTO on Lenny's](../research/sources/lenny-podcast-block-dhanji-goose.md) (first-party).
- **Evidence row (mandate with monitoring):** staff say AI use went from encouraged to required over about nine months, with tool- and token-level monitoring and AI-proficiency questions in performance reviews. Block says "100% of Block employees are using AI tools" (Q1 2026). Cost: fatigue and distrust ("People are fed up with AI"). Evidence: [Guardian](../research/sources/guardian-block-workers-ai-cant-do-their-jobs.md); [HRD](../research/sources/hrd-block-staff-dispute-ai-layoffs.md) (independent); [Q1 2026 letter](../research/sources/block-q1-2026-shareholder-letter.md) (first-party).
- Key question: would our org accept usage monitoring as an adoption lever, and what does it cost in trust compared with distribution plus champions? — *answered by:* HR and works-council or employee-relations owners; a staff pulse survey — *affects:* mandate, champions, distribution-led.

## target-user
- **Evidence row for "Every employee including non-engineers":**
  - Block's CTO says non-technical staff (legal, risk, operations) gain most. Enterprise risk built its own self-service tool, "weeks of work into hours".
  - About 80% of App Kit users are outside engineering.
  - Query Expert reaches over a third of the company.
  - PMs are named only generically ("product").
  - Evidence: [CTO](../research/sources/lenny-podcast-block-dhanji-goose.md); [App Kit](../research/sources/block-eng-app-kit-localhost-to-launched.md); [data foundation](../research/sources/block-eng-data-foundation-automated-analytics.md) (first-party).
- **Evidence row for "Generalist product role in a lean pod":**
  - Feature teams of about 14 became squads of 1-6.
  - "All of our product managers are shipping PRs."
  - The one open Square PM role asks for AI prototypes and PRs.
  - The Cash App growth manager role "blurs growth and product" and names Claude Code or Goose.
  - Evidence: [Jennings](../research/sources/a16z-owen-jennings-block-all-in-on-ai.md); [PM job post](../research/sources/block-careers-staff-pm-post-checkout.md); [growth job post](../research/sources/block-careers-growth-manager-activation.md) (first-party).

## pm-agent-evaluation
- **Evidence rows for "Self-reported time saved" and "Delivery throughput", with no product-outcome measure:**
  - Hours saved: 8-10 hours a week (self-reported). "Manual hours saved by goose" was the single weekly metric, with a 25% target, from an unpublished formula.
  - Throughput: production code per engineer up 40%+ (to Feb 2026); code changes per engineer up 2.5x (Q1 2026); 130 Square features in H1 2026 (3x+, "feature" undefined).
  - Analysts judge the cut on financials.
  - Evidence: [CTO](../research/sources/lenny-podcast-block-dhanji-goose.md); [Sequoia CTO](../research/sources/sequoia-training-data-dhanji-goose.md); [Q4 2025 remarks](../research/sources/block-q4-2025-earnings-prepared-remarks.md); [Q2 2026 call](../research/sources/fool-block-q2-2026-earnings-call.md) (first-party); [Payments Dive](../research/sources/paymentsdive-block-leans-into-ai-future.md) (independent).

## Cross-cutting key questions
1. **Role collapse vs handoff artifact.** Block's answer to the research → intent → plan seam is to have fewer people do more of the arc (DRIs, squads of 1-6, PMs shipping PRs). Can our target org adopt any part of that, or must we fund a handoff artifact instead? — *answered by:* a task-level time study with 5-8 teams; an org-design owner — *affects:* target-user, work-structure, intent-shaping-and-spec, session-persistence-sharing.
2. **Separating the AI effect from the org effect.** Block's CTO credits the functional reorganisation over any tool, and the 2025 cut was "not replacing folks with AI". How much of Block's reported gain would we get from the agents alone? — *answered by:* a pilot that holds the org constant — *affects:* pm-agent-evaluation, sequencing, adoption-model.

## Proposed new dimension (for the director)
- None. The org-shape question (`ai-flattened-org` theme) bears on target-user and work-structure. It could become a dimension, "how far roles are collapsed around agents", if other ecosystems (Airbnb, Spotify) show the same choice.

## Relevance to the project
The only first-party description of **Trailhead**, Stripe's internal documentation tool, and the clearest Stripe evidence on how tacit knowledge was made agent-ready *before* Kai: Stripe built Trailhead after its six-monthly engineering survey kept flagging stale, fragmented docs; its key features make owners **verify** docs and keep them current, or they "drift away and get archived"; only once Stripe "trusted that we understood all of our documentation and that there was good information hierarchy" did it put an LLM bot over it (browser, Slack, IDE). The complaint then dropped steeply in the next survey. Strong evidence that curation and verification, not just mining, precede reliable agent answers.

## Themes
- tacit-knowledge-capture: docs capture requires an owner-verification loop with archiving of unverified pages (Escorce-Jones answer, late in the panel).
- org-context-grounding: an LLM docs bot was built only after the docs were trusted: "questions about documentation that we then felt comfortable, like were going to be accurate".
- legible-org-for-agents / compounding-context-repo: "we really tripled down on trying to solve that problem because it just seemed to come up in every" survey.

## Key points
- Stripe surveys every engineer every six months on tools and developer experience; ~18 months before (so ~late 2022), "struggling to find good documentation" was a top complaint.
- After the Trailhead investment and promotion, "you can just see the steep drop-off" in that complaint.
- Bot surfaces: browser, Slack, IDE.

## Notable quotes
- "it has a bunch of really cool features, especially around making sure that people verify their documentation and make sure it stays up-to-date. Otherwise, it kind of drifts away and gets archived."

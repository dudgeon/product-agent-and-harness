## Relevance to the project
The lead thread is practitioners noticing, in early 2026, that AI build speed has outrun discovery and strategy. A legal-tech founder-PM worries about a "Frankenstein product" from getting through the roadmap too fast; replies propose two-way-door shipping, name "customer attention" as the next bottleneck, and one sums it up as "building got cheap, but confusion didn't". This is grassroots support for the project's "the bottleneck moved to intent" claim, and for the risk that speed erodes coherence. The estimates thread adds that dates slip because "the spec wasn't solid enough", and the Claude Code + Codex thread shows practitioners using a second vendor's agent as reviewer. Bears on intent-shaping-and-spec, review-and-autonomy, model-provider-coupling and sequencing.

## Themes
- intent-factory-before-discovery: "building got cheap, but confusion didn't ... trying to slow down on decisions, not on execution" (thread 1, a PM). Another: "what to ship" and "whether to ship" are converging; build first, refine later; more input context about why and what expectations exist makes output "more likely ... on-target and shippable" (thread 1).
- product-coherence-over-automation: legal-tech founder-PM holding back to put "enough reps in discovery" to avoid a "Frankenstein product" (thread 1).
- human-judgment-pm-jobs: a PM lays out three uses of faster engineers: more delivery, lower burn, or spend half the time on customer discovery and validation; he favours the third, "outcomes over outputs" (thread 1). Another names customer attention as the new bottleneck: changes that need users to learn or change behaviour still warrant a slow approach (thread 1).
- agent-ready-intent: "estimates almost always slip because the spec wasn't solid enough when we scoped the work" (thread 4, a founder); others recommend ranges, timeboxed discovery, and an end-to-end working slice within the first 20% of a project.
- human-review-gates / harness-portability: several members pair Claude Code for building with Codex as reviewer or unblocker; one has the two agents share a page they both poll, with only Claude allowed to push to the remote; another calls multiple models on every prompt "like adding additional teammates" (thread 3).

## Key points
- Speed onset: members date the jump to the previous few weeks, crediting Claude Code agent teams plus Opus 4.6 (thread 1).
- Small-team context: a two-person startup ships several times a day, including bug fixes during customer calls and a one-day onboarding redesign, because the risk of shipping something bad is low for them (thread 1).
- Codex was described as good for narrow review and fixes but prone to "rabbit holes" and over-engineering on big-picture work (thread 3).

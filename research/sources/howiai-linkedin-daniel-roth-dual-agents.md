## Relevance to the project
A non-engineer (LinkedIn's editor in chief) ships iOS apps with a two-agent Claude Code setup, "Bob the Builder" and "Ray the Reviewer", which plan, build, and review (including security) each other's work, with Markdown files as long-term context and branch-based development. It is a small, personal example of builder/reviewer separation and file-based memory, and of a non-PM taking a "picky customer" stance rather than a PM stance. Downgraded from medium to low: no transcript was available, so only the show notes could be used, and the subject is a personal side project rather than product work in an organisation. Bears lightly on work-structure (one job per agent) and review-and-autonomy.

## Themes
- one-job-per-agent / human-review-gates: "How to set up a dual-agent Claude Code system (builder + reviewer)"; chapters "Introducing Bob the Builder and Ray the Reviewer" (10:38) and "How Bob and Ray work together to build features" (13:50); the episode summary says the agents "plan features, write code, review security".
- memory-architecture: "Why saving everything as Markdown files creates long-term context" (show notes).
- non-engineer-builders: built and shipped multiple App Store apps, including Commutely (a New York train-tracking app), "without ever learning how to code" (show notes; 21:12, 25:00).

## Key points
- Prioritises features with "AI-ranked impact vs. build time" (05:56); also had Claude draft a retention plan (09:47).
- "Managing AI agents like managing a team" (17:39); "Why Daniel focuses on learning the process" (14:37); branches even when AI writes the code (16:34).
- Positions himself as a "picky customer" rather than a PM (23:06).
- Uses Microsoft Copilot at work for an end-of-day "What did I drop the ball on?" review (32:10).

## Relevance to the project
A solo, live walkthrough for non-technical PMs: Claire Vo builds a "personal project hub" in Cursor, a Next.js app that displays Markdown docs from a docs folder and prototypes from a prototypes folder, adds an agent-instruction file for writing PRDs, uses it to write a PRD, then has the agent build a clickable prototype from that PRD. It is a simple illustration of PRDs as files next to prototypes in a repo with a PRD-writing instruction file, the pattern the project calls docs-as-code; and of a vibe-coding platform overbuilding from a PRD. Low relevance: a beginner tutorial with no team or organisational dimension, from a host who sells a PRD tool.

## Themes
- docs-as-code-prd: PRDs and docs stored as Markdown in a local Git repo, rendered in a web app, edited by AI, with change tracking via GitHub Desktop (32:14-33:45). Same structure as Notion's prototype playground filed separately: one folder for docs, one for prototypes.
- prd-agents: an `agents/prd.md` instruction file (under 500 lines; role, principles, PRD structure, checklist), generated by the agent and edited to favor technical over business requirements; "in Claude Code, it's called a skill" (26:11-29:12). The resulting PRD was "too long for a solo founder", so she would add a length rule (32:14).
- prototyping-agents-limits: v0 "went like ham on the requirements" from a deliberately simple PRD, adding file management and a coding sandbox, and threw errors; she abandoned it after about 10 minutes and started from an empty folder in Cursor (12:25-15:29). She attributes this to platforms competing on completeness: "a lot of scope creep be built into how these more agentic implementations ... work" (12:25).
- non-engineer-builders: advice for beginners: start in a browser vibe-coding tool to see the app, pick Python or JavaScript, use GitHub Desktop for Git, avoid auth and databases in prototypes (9:23, 24:41, 36:47).

## Key points
- Flow: PRD in ChatPRD, failed attempt in v0, rebuild in Cursor 2.0's agents view with the Composer 1 model ("so freaking fast"), run locally, initialize Git, add PRD agent, write a PRD, build a prototype from it, update the README for "agents as well as other engineers", restyle (43:20 recap).
- Starts with a PRD because "you just get better results out of the next step" (7:50).

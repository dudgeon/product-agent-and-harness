## Relevance to the project
One thread (April 2025) on getting hesitant engineers to adopt AI coding tools. It is a snapshot of early adoption friction: mandates backfire when they come from outside the team, while demos by peers, low-stakes show-and-tell sessions, and an assignment on an unfamiliar codebase work better; senior engineers' objections were about maintainability and destructive actions, not just habit. Useful only as background for the adoption-model dimension (mandate vs peer pull); it predates the agentic tools the project focuses on and says nothing about PMs. Downgraded from medium to low.

## Themes
- org-learning-loop: an "AI exploration session" where product and dev each did a 10-15 minute show-and-tell "ended up spurring the devs to adopt Cursor across the team"; a peer demo by an existing user helped win over a reluctant team lead (thread 1).
- enablement-by-product: one org paid for both Cursor and Windsurf team seats and said "this isn't optional, choose which one"; hesitant users who disliked Cursor adopted Windsurf. Another org's top-down mandate "didn't go very well" because it did not come from the engineers (thread 1).
- agent-failure-modes: a senior engineer reports Cursor turning a 10-line edge-case fix into a 170-line method after about six revisions; another reports someone losing all their Docker containers by trusting AI code; an agency owner says agent mode introduces bugs and wrong libraries, takes many steps, and leaves him knowing the code less well (thread 1).

## Key points
- What converted a reluctant team lead: a non-developer manager built a working app purely by prompting and showed it; the lead was asked to build an integration in a codebase he had never seen, where AI help was obviously useful; a peer demo (thread 1).
- Objections worth taking seriously: editor choice is personal and tools are converging, so mandate the capability not the editor; "Writing code has never been the bottleneck; the real challenge is understanding what to solve, how to solve it, and how to integrate the solution"; large monoliths and legacy systems make the tools add friction; destructive mistakes (deleting a production environment) carry career risk, so resistance has rational roots (thread 1).

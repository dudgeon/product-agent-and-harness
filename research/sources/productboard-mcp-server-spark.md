## Relevance to the project

Productboard puts the spec on the initiative/feature object and exposes it to coding agents through a remote MCP, with an 'Agent Knowledge' document area. It is the clearest example here of a PM tool deliberately acting as the upstream half of a spec-to-coding-agent handoff, which is the meta-harness boundary.

## Themes

- agent-ready-intent: specs live in a Specification tab on initiatives, features and subfeatures; Spark's 'Write spec' skill drafts them; agents read, edit, comment and update status.
- harness-portability: documented for Claude Cowork, Claude Code, Cursor; remote MCP at mcp.productboard.com, browser sign-in, agent sees only what the user can see.

## Key points

- Beta, included with Spark-enabled workspaces at no extra cost; admins enable it under Settings > MCP Server and choose roles.
- Agent capabilities: search by keyword/meaning/owner/tag; read specs; propose and apply edits; read/post comments; update status; list/create/move/rename documents and folders in Agent Knowledge, teamspaces, folders and personal spaces; writes appear in version history.
- 'Open in' button (Labs) sends a spec to a coding tool.

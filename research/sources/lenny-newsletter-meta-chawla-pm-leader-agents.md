## Relevance to the project
Best single account of PM-leader agents covering review prep, nightly decision tracking and analytics, and it states real failure modes. Describes Chawla's personal system ("N of one"), not a Meta-wide platform; the post carries sponsor slots (Glean, Framer) but is not labelled sponsored content; no independent metrics. Bears on which PM jobs to build agents for and how long tuning takes.

## Themes
- status-update-agents: agent drafts product-review doc, flags three questions, suggests five invitees, records decisions; overdue decisions shown red next morning; nightly agent scans diffs, email, chat, docs for a decision punch list (case 5).
- spec-becomes-prototype-and-evals: the PRD became a one-paragraph problem statement plus prototype, with an eval set added for ML-heavy work (the intro overstates it as "every team").
- outcome-measurement-gap: no independent metrics; system was inaccurate at first and needed about six months of nightly tuning.
- org-context-grounding: analytics agent answers data questions in about five minutes using queries the data scientist already wrote; depends on Meta's habit of documenting experiments.
- human-review-gates: one brief dropped all source links; not rolled out everywhere, so humans check outputs.

## Key points
- Agent drafts the product-review doc and records decisions afterward; overdue decisions appear red next morning.
- Nightly agent scans diffs, email, chat and docs to build a decision punch list.
- Analytics agent answers data questions in about five minutes by reusing data-scientist queries.
- PRD replaced by problem statement + prototype; eval set added for ML-heavy work.
- Caveats: each night the system compares its predicted review comments with the ones he actually left; inaccurate at first, "Six months in, it's accurate"; one brief lost all source links because "the HTML was getting clunky"; review agent only in parts of his org; post carries Glean and Framer sponsor slots.

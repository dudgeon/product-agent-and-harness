## Relevance to the project
A consultancy's governance-focused assessment of OpenCode, written for enterprise rollout. It lists what a regulated organisation would have to add before standardising on an open harness: permission profiles, provider allowlists, approved MCP servers, plugin review, token storage rules, logging and audit. Independent of OpenCode but the publisher sells adoption consulting (no disclosure of ties).

## Themes
- skill-supply-chain-security: plugins and custom tools "can execute arbitrary code"; plugin handling "should be treated like installing executable developer tooling"; remote MCP OAuth tokens stored locally in a file.
- build-vs-buy: "Do not standardize it until security and governance are explicit."

## Key points
- Ring: Assess, for developer-tooling teams and advanced users.
- "most permissions default to allow"; built-in bash and write tools; many config layers and merge rules complicate managed rollout.
- Suggests a controlled pilot on realistic tasks before Trial.

## Relevance to the project
A PM builds a tool that runs a feature description (typed, or imported from a Linear issue) past five AI personas at once, returns likes, concerns, a score and a suggestion from each, and lets the PM phone one persona through an ElevenLabs voice agent. It matters to the synthetic-users question because the post claims the personas are "grounded in real world data", yet the data folders were mock data generated in Claude Cowork; so a reader can't tell real grounding from synthetic grounding, which is the risk NN/g warns of ([NN/g note](nngroup-synthetic-users.md)). It is also a worked example of a non-engineer chaining Claude Projects, Cowork, Claude Design, Claude Code, Cursor and third-party APIs into one internal tool. It is the author's own build; there are no results or validation against real users.

## Themes
- synthetic-users-limits: the author says it is "not meant to replace speaking to real users" and that personas are divisive, but positions the tool for testing assumptions from several perspectives at once (intro; closing). No check of persona verdicts against real feedback is reported.
- ai-synthesis-hallucination-risk: the attitudinal, behavioural, contextual and interview data were generated by Cowork as "real world examples" and then used to derive the personas, so the personas' specific quotes and patterns (for example a payroll manager who checks the register three times) trace back to model-written data (section 1).
- research-synthesis-agents: personas are derived by a Claude Project loaded with three NN/g articles as guidance; the author suggests re-reading transcripts to check the result (section 1). The closing idea is to keep personas current from live support and analytics data.
- non-engineer-builders: build path is Claude Design for the first UI (asked to avoid a "brochure" look), Claude Code with Cursor to run it, then Claude Code adding a settings screen for API keys, a Linear import and, after a plan-mode step, the voice call (sections 2-3).
- prototyping-agents-limits: the first design looked like a brochure until the author asked for a modern web-app look; permissions tweaks were needed for the voice agent (sections 2-3).

## Key points
- Opening context: shipping volume (release counts per company from Releasebot, counting releases not features) and a claim that Anthropic's roadmap is now one month long (attributed to Felix Rieseberg, second-hand). The point: shipping fast doesn't mean users want it.
- Example company: a fictional HR SaaS ("Kova") with five personas: solo head of people, payroll manager, IT admin, CFO, and the "involuntary" employee user.
- Avatars made with Gemini image generation in a stop-motion clay style.
- Voice agent: ElevenLabs Agents with a Claude-written system prompt that sets the persona's role, goals, frustrations, speaking style and call rules (short spoken answers, stay in character, push back). On each call the app sends the base persona plus the feature description and that persona's verdict, score, quote, likes, concerns and suggestion.
- Downloadable folder structure and finished app offered to readers (not reviewed).

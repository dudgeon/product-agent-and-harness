## Relevance to the project
RAPID is the best-known decision-rights scheme (Recommend, Agree, Perform, Input, Decide). It maps cleanly onto how agents could be placed in a multi-party PM session: an agent can plausibly hold R, I or P, while D stays with a named human. The page states the rules but offers no evidence.

## Themes
- decision-rights-for-agents: "one decider for each decision"; one recommender per decision (body).
- autonomy-alignment-placement: start with high-value or high-frequency decisions rather than applying it everywhere (body).

## Key points
- Roles: Recommend leads the process and builds the proposal; Agree checks feasibility, often legal or regulatory; Perform executes; Input supplies expertise; Decide makes the call and commits the organisation.
- Agree input must be reflected in the proposal but is not a veto; unresolved R-vs-A disagreements go to D.
- If a group holds D, agree in advance how it decides (majority, chair's call).
- Claimed benefits (no data shown): clearer accountability, shared vocabulary, faster execution (vendor-claim; RAPID is a Bain registered trademark).
- My judgment: for agents, the useful part is "single D, R does the legwork"; this matches Shopify's "hand off the decision, not the investigation" (shopify-engineering-river-vulnerability-remediation), with the agent as R.

## Relevance to the project

The verbatim definition of relationship kinds in Atlassian's work graph. Corrects the earlier pass: there are four kinds (canonical, activity, logical, inferred), not three; "logical" relationships are the union views (e.g. all documents a user created regardless of source) that an agent would query. Useful as a model for how a meta-harness could express links between specs, work items and decisions across tools.

## Themes

- product-artifact-primitives: "there are four types of relationships: canonical, activity, logical, and inferred." Canonical examples: "A work item belongs to a project", "A document has a parent document", "A pull request is in a repository", "A commit is associated with a work item".
- legible-org-for-agents: logical relationships such as `AtlassianUserCreatedDocuments` give "a unified view of all documents a user has created, whether they're Confluence pages, external documents, or other document types"; `AtlassianUserAssignedWorkItems` does the same for Jira and external work items.

## Key points

- "Every relationship has a type: For example, UserCreatedIssue, ParentIssueHasChildIssue, or IssueAssociatedPR." Directional from/to.
- Connectors create canonical relationships with `parentKey`, `containerKey`, `createdBy`, `owners`, or `associations`.
- Activity relationships are "automatically generated by Atlassian systems"; inferred ones are "derived by Teamwork Graph itself" (e.g. top collaborators).

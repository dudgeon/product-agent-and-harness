## Relevance to the project

The canonical statement of the "single-player usefulness first" half of the planned cold-start strategy for a dependency-mapping agent: attract users with a tool that is useful alone, then move them into a network whose value depends on others. It bears directly on whether an agent that reads raw sources (repos, tickets, policy pages) can carry feature teams until platform and gate owners publish context. It is an investor's essay with consumer examples, not evidence about internal tools; its claim is a pattern, not a measured effect.

## Themes

- **two-sided-cold-start**: single-player tools build "initial critical mass" and the network then supplies long-term value and defensibility; "Think of single-player tools as kindling" (body). Anecdote.
- **enablement-by-product**: the tool has to be worth using with nobody else on it; the network is a later layer, not the reason for first use (body). Anecdote.

## Key points

- Pattern: a product attracts users as a single-player tool, then gets them to join a multiplayer network over time (opening paragraphs).
- Examples: Delicious (bookmark storage as the tool, tag-based discovery as the network) and Instagram (free filters as the tool, the feed as the network) (examples section).
- Caveat in the essay itself: this is one path among several; Facebook and Twitter grew without a single-player tool. Starting a network from scratch is "very hard" (closing paragraphs).
- For the project: the analogue of the "tool" is the agent's raw-source dependency map for one feature; the "network" is the owner-curated context layer and the compounding record of past features. The essay says nothing about how the network side gets recruited once the tool has users; that is the open part of the strategy.

## Notable quotes

- "The network creates the long term value for users, and defensibility for the company." (body)
- "But starting a network from scratch is very hard." (body)

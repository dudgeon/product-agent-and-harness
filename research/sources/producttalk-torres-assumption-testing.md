## Relevance to the project
Torres's assumption-testing practice is the product-discovery version of an open-question register: assumptions are listed, typed, mapped by importance and evidence, and each test is logged with success criteria set before it runs. It gives a PM agent a ready schema for a discovery process artifact that a team can share over weeks.

## Themes
- process-artifacts-as-coordination: each test tracked with six attributes: assumption, audience, test details, success criteria, results, and how the team acted (Trello card for tasks, Miro board for ongoing tests) (body).
- experiment-decision-rules: define success before testing, "a line in the sand", so results are judged against a threshold, not "good enough" (body).

## Key points
- Five assumption types: desirability, viability, feasibility, usability, ethical; categories exist to surface risk, not to be debated.
- Surfacing methods: story mapping (best for desirability and usability), walking the opportunity solution tree, ideal customer profile, data-policy audit, premortem.
- Phrase assumptions as what must be true, specifically; it is easier to test whether customers will do something than whether they won't.
- Prioritise with David Bland's assumption mapping (importance vs existing evidence); test only the riskiest (important, little evidence).
- Four test types: prototype tests, one-question surveys, data mining, research spikes.
- My judgment: the register itself is checklist-like (fields), the prioritisation is rubric-like (two axes), the test design is judgment; a three-layer artifact.

## Relevance to the project
A practitioner guide, drawn from teaching more than 500 PMs, to making AI prototyping a team practice rather than isolated experiments: component libraries (from screenshots, a Chrome extension, or real code and the Figma MCP), a "baseline and fork" workflow, and a map of which fidelity of prototype to use at each lifecycle step, with a full example PRD used as the prompt. It is useful for intent-shaping-and-spec because it treats the prototype as a communication artifact inside the PRD that surfaces edge-case questions faster than prose, while stating plainly that prototype code is "mostly useless" to engineering unless built on the real component code. Dated (June 2025) and written by someone selling a course.

## Themes
- prototyping-agents-limits: "the code generated by AI prototyping tools is mostly useless to your engineering team (unless your components are built using your existing code)"; it doesn't follow existing patterns or libraries, may not be the same language; useful only for specific interactions like animations (Step 5). "Prototyping doesn't really impact development timelines, so expect two to six weeks" (Step 5).
- spec-becomes-prototype-and-evals: at the PRD step, demo the high-fidelity prototype live to engineering to generate edge-case questions (what does the accuracy score mean, which sources, what content to exclude, how answers are vetted), "a much faster and easier way ... than hoping an engineer reads your whole PRD" (Step 3).
- artifact-standardization: component libraries and "baselines" (a high-quality reproduction of the current product that is never edited, only forked) are shared team artifacts that keep prototypes on-brand and make onboarding easy (Component libraries; Workflow 1).
- prd-agents: the Reddit Answers example PRD (overview, user stories, phased implementation, design system tokens, components, data model) is itself the prompt that generated the discovery prototype (Step 1).
- pm-tool-connectivity: the Figma MCP (four actions: get code, get variable definitions, get image, get Code Connect) lets Cursor extract tokens and CSS to build components from a real design library (Method 3).

## Key points
- Two problems he sees most: prototypes not good enough to show customers or executives, and teams working "in silos" with no handoff guidance (intro).
- Three component-library methods, in rising effort and fidelity: screenshots plus a prompt (any tool); Magic Patterns' Chrome extension; real code, which needs engineering to make the front end run locally with mocked API responses, "most realistic in smaller companies or those with more technical designers and PMs" (Method 3).
- "Reflection" prompt for refinement: list the differences between the screenshot and your implementation, "Don't code" (Method 1).
- Fidelity is a choice by context: AI prototyping adds a "medium fidelity" between napkin and polished Figma; mid-fi is fine to explain an interaction to an engineer, high-fi for a CEO funding pitch (Workflow 2).
- Lifecycle map with time estimates: discovery mid-fi in about 20 minutes, internal only; roadmap/alignment high-fi in 20-60 minutes; PRD and mocks with the prototype embedded, two-plus hours of engineering discussion; user interviews with the prototype, 3-5 days, optionally with embedded surveys; engineering delivery, 2-6 weeks unchanged.
- Practical fix: paste the real logo URL or SVG, since tools draw "an uncanny-valley version of your logo" (Bonus tip).

## Relevance to the project

Atlassian's own answer to "where does a PRD live and how does it link to Jira": a Confluence page template whose header table and Options table link to Jira epics/issues with `/jira`, with named sections (objective, success metrics, assumptions, options/user stories, supporting docs, open questions, out of scope). It is a page template, not a typed object: Jira links are embedded Smart Links, not a schema relationship. No mention of Jira Product Discovery ideas.

## Themes

- artifact-standardization: sections: "PRD basics and team roles" (target release date, status, core team), "Objective", "Success metrics" table, "Assumptions", "Options" table (requirement, user story, importance, Jira issues), "supporting documentation" (mockups, diagrams), "open questions" (with answer and date), "out of scope".
- docs-as-code-prd: the PRD is a Confluence page; "You can type /date to quickly add your target release date, "/jira" to link directly to Jira epics or issues, and @ mention team members".
- product-artifact-primitives: the Options table "has spots for you to come up with a user story ..., assign a level of importance, note any Jira issues"; the page is pitched as "a single source of truth" that pulls in "research and specs".

## Key points

- Template categories: Product Management, Software & IT, Recommended; "Page Template".
- Jira linkage is by embedded issue links in tables, not by a PRD-to-work-item relationship type.
- No link to JPD, goals, or Atlassian Home projects on the page.

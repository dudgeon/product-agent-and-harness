## Relevance to the project

Defines Productboard's native object tree: products, components, features, subfeatures, with insights linked to features, and a separate objective/initiative layer. This is the canonical 'insight to feature to objective' PM data model that a meta-harness may need to map to or avoid duplicating.

## Themes

- feedback-triage-agents: feature has an Insights tab for linked insights; notes land in an inbox (web-search summary of a 2019 post, unverified here).

## Key points

- Hierarchy: Product > Component > Feature > Subfeature. Features can be imported from spreadsheet, Jira or Zapier.
- Feature tabs: Detail (description, subfeatures, files, related releases/objectives/integrations), Insights, Health, Portal.
- Objective > Initiative > Feature layering (from search summary of support/blog pages, not directly fetched).

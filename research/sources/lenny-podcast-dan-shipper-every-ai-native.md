## Relevance to the project
A 15-person company (newsletter, several AI products, a consulting arm) describes an operating model where engineers write no code by hand. Three ideas are useful for us. **Compounding engineering**: when the job becomes "typing PRDs", write a prompt that turns rambling thoughts into a PRD so each next PRD is cheaper, and share the prompt library in GitHub (bears on intent-shaping-and-spec and capability-distribution-trust). **An AI operations lead**: one person outside the day-to-day who turns repetitive work into prompts and workflows and drives behaviour change (adoption-model). **Adoption predictor from consulting to large firms**: whether the CEO uses a chatbot daily, plus weekly prompt-sharing meetings and usage-stats emails. Small, AI-enthusiast team and a firm that sells AI consulting, so not representative of a regulated enterprise.

## Themes
- compounding-context-repo / prd-agents: "for every unit of work, you should make the next unit of work easier to do"; since engineers "spend a lot of time essentially typing PRDs", they write a prompt toward "a sort of platonic ideal of a PRD" that turns rambling thoughts into one (41:58); the prompts are Claude Code slash commands kept in a shared GitHub repo (43:52-44:22).
- enablement-by-product / org-learning-loop: head of AI operations meets the CEO weekly; every repetitive task goes on a list and she builds prompts and workflows "so that I and everyone else on the team are just automating as much as possible" (30:16). The catch: "you have to make sure it gets used"; the editor-in-chief had to learn to ask "did you put this through the prompt yet" (30:16, 31:51).
- org-learning-loop: the style-guide copy-edit prompt was turned by an engineer into a Claude Code command that scans the whole codebase for copy, opens a PR and sends it to the editor to approve: "suddenly your engineering team is writing marketing copy in the style you want" (34:18).
- human-review-gates: engineers "definitely are looking at code ... you're doing a code review before you do anything" (52:33); and "we're not at a point yet where the people that work at Every could do what they do if they didn't know how to code" (53:26).
- one-job-per-agent: the two-person Cora team runs "15 Claude Code instances" plus other agents (Friday; Charlie, which lives in GitHub and is invoked on a PR); they value agents' different "perspectives" and "taste"; "It's definitely not one agent to rule them all" (41:44, 44:22-46:30).
- non-engineer-builders: "people are truly sleeping on how good Claude Code is for non-coders": it processes every file into a notebook over many turns rather than stuffing context (7:10-9:14).
- pm-persona-role-expansion: "allocation economy": management skills (evaluating quality, vision, taste), held by about 8% of the workforce, become universal as everyone manages agents (50:33).

## Key points
- Cora (AI email assistant) built by two engineers: 2,500 active users and "millions of emails" in private beta; show notes say under $300k total cost (41:58-43:29, takeaways).
- Consulting playbook (about $1M last year, expected to double): interview teams, report plus a chatbot over the interviews and a dashboard of which teams are keen and where leverage is; then four weeks of team-specific training, an hour a week, with exact prompts per job; then automations (1:09:35-1:11:53).
- Adoption heuristic: roughly 10% curious, 10% refusers, 80% "if you tell me how to do it for my job, I'll do it" (1:10:17). A $10B hedge fund client's CEO memo said "I wrote this email with ChatGPT, and you should too"; weekly prompt-sharing meetings and usage-stats emails surface early adopters (1:11:53-1:14:32).
- Outcomes so far: clients "can do way more work ... without having to hire more people"; no layoffs seen in his engagements; he calls the Klarna CEO's automation claim "bullshit" (1:15:34).
- Junior staff accelerate by recording mentor feedback into prompts: "he never made the same mistake twice" (49:42).
